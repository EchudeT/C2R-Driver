# 粗路径、关键前提与 v1 知识积累

状态：核心代码已接通，完整离线回归 413 项通过；回归启动后的局部调整另经 25 项针对性测试通过。
未进行本版真实模型端到端实验；检查命令、全库静态检查问题和证据限制见
[验证记录](audits/route-guided-2026-10-03/verification.zh-CN.md)。

## 方法

保留 v1 的固定源码/环境、带来源的知识库、契约及实际验收，用粗路径组织前置分析。
顺序为：源义务 → 主路径草案 → 会改变设计的关键前提 → 原文或最小探测 → 契约/行为工作包。
粗路径不是实现任务列表；设备入口、资源获取、发布、触发、清理可以属于同一个完整行为。
路径不能裁剪源义务，分析须核对源入口的主要退出和失败分支。

## 单一分析材料

正文在同一 Markdown 中。小型 route 索引只保存段落引用、源码位置、ID 和关系：
main_route、behaviors、contracts、premises，以及可选 learn（要沉淀的前提 ID）。
不复制第二份目标研究或契约正文。段落使用唯一的 Markdown 标题引用，无别名或模糊匹配。
普通实现细节不建立前提；前提仅限不同答案会改变接入方案或使多个后续行为返工的问题。

契约源义务和判别观察保持冻结；目标接入路径和具体承担方式允许根据反证局部修订。
控制器按引用依赖生成工作包、计算变化影响，不对自然语言声称形式语义验证。
初始粗行为计划直接用于实现调度，避免实现模型重新规划一次。

## 最小探测

固定版本源码能回答的问题不执行探针。需要执行时，绑定一个已有关键前提，说明问题、
不同答案的设计后果和最小观察，调用已验证环境中的执行器。失败、未运行和未知不能写成成功。
没有关键缺口就没有探测；不逐路径节点探测，不增加新的固定模型阶段。
执行收据包含输入、环境、脚本和结果身份，变化后不能把旧观察当作新输入的验证。

## 局部修订与验收

实现保持一轮一个完整行为。改变路径/前提只影响引用它的行为及显式依赖者；其余进度保留。
源码始终保留。普通源码修改不触发路线重审或行为进度失效；已有引用文件变化也不单独构成返工理由。
工作者发现具体反证并显式修改路线、前提或行为定义时，才按这些计划关系更新进度。
源码改动由当前行为检查和最终验收处理，不再额外要求前提续证。
同一行为目标不变的路线修正可以在原回合完成，不为确认更新另开一轮。
改变行为边界不能借一个 done 越过多个行为。
修改源义务或测试标准继续走已有显式契约修订，不能通过改路径偷偷缩小范围。
最终控制器验收保留，不以路径闭合、探针成功或知识条目替代。

## 分析经验进入知识库

保留 v1 的来源与检索机制，选择性沉淀有复用价值的接入条件、接口前提、失败模式和探测配方。
由同一分析段落指向原文/受控观察；不要求另外撰写一套知识报告，不整篇灌入对话和临时猜测。
learn 默认为空。选择的前提必须已经有证据，带适用版本、条件和限制。
观察与模型解释分开；未证实猜测不成为已验证经验，历史 PASS 不转为新任务 PASS。
有共享库配置时向本地共享库追加有证据引用的解释；当前任务的已固定检索快照不被暗中改写。
下一驱动按需检索并检查当前版本适用性，无强制预读或查询配额。

## 完成核对

必须验证：源码依据充分时零探针；具体缺口可运行一次受控探针并保留失败；旧观察不能支持
变化后的输入；初始行为从分析计划生成；局部变化不重置无关进度；单行为 done 约束保留；
源契约不能被路径修订削弱；知识选择性积累并可被后续任务检索；不兼容旧冻结任务，仅保留旧记录用于审计；
README/架构文档状态和实际代码一致。离线测试不能声称新的模型降本结果。


## 实现入口与提示词

- `target_study/service.py`：冻结同一报告及 `analysis_route`，控制器登记契约。
- `migration/route_model.py`：纯引用关系、行为工作包及局部变化计算。
- `migration/route.py`：保存明确的路线修订，保持源契约正文与断言。
- `migration/route_probe.py`：一个问题的一次受控执行，失败和原始输出保留。
- `knowledge/route_learning.py`：选择性发布带来源的解释，不改当前任务检索快照。
- `environment/bootstrap.py`：基线构建/启动收据直接进入环境交接，不要求设备探针。

可独立审阅的提示词在 `src/driver_port_factory/data/prompt-packs/default/`：
`evidence-selection.md`、`environment-task.md`、`analysis-task.md`、`behavior-job.md`、
`delivery-task.md`。`orchestration/protocol.py` 提供简短提交接口，不重复完整研究流程。

`driver_checks.analysis` 提供 `inspect`、`probe`、`revise`；inspect 是可选引用检查，
不是必经调用。正文为 `report.md`，索引为同名 `report.route.json`。
正文推荐直接以 `R1/B1/C1/P1` 为标题，索引默认用 ID 定位，不重复填写长标题。
源码已能支持的前提只填写路线、状态和源码引用，无需探测字段。只有实际探测时使用
`question_section` 引用稳定的问题段落，`probe_receipts` 填控制器返回的短 ID；
`section` 默认等于 ID，指向结论及适用限制。补充答案不改变探测问题。实现中保留的原观察仍是历史证据，不因普通源码编辑强制重跑；新引用的观察
必须对应提交时的执行输入，不能把旧观察冒充当前源码验收。

知识选择为空或未配置共享库时无需写入；库不可写时记录 NOT_PUBLISHED，交付不因此返工。
历史经验只帮助定位和判断适用性，不能替代当前驱动的实际验收。


## 提交格式与同轮修正

分析提交与最终登记共用同一校验入口。`codex submit` 在写提交收据前检查索引、源码位置、
已有探测收据及可选检索证据；相互独立、当前可检查的问题合并反馈。解析失败时先修对应
文件，不能声称能预知修复后才可见的问题。失败提交不占本轮提交名额，模型在同一回合修正后重交，
无需结束调用再由控制器发起恢复。成功提交仍冻结实际内容，后续控制器再次验证，不等于驱动验收。

索引省略 `section` 时使用 `id`；省略 `depends_on`、`premises`、`learn` 和前提的
`sources`/`probe_receipts` 时使用空集合；前提仍须显式给出 `status`。不根据散文猜测
语义，不用标题别名或模糊匹配，不把错误探测记录自动转成源码证明。没有检索证据时不要求
空的 `.probes.json`；记录 NO_RETRIEVAL_REQUESTED，不声称模型没有查过知识库或语义已被验证。

这是新任务协议；旧冻结实验使用自己的控制器副本，不迁移或热更新。针对小模型减少填表负担，
离线回归验证接口行为，不能据此保证 luna 永不出错或宣称真实费用已下降。

## 工作包粒度（对照 v2 修正）

B 是完整实现工作目标，C 是源义务，R 是粗路线。多个 C、源函数、测试或 R 内部步骤不要求多个 B。
简单内聚的驱动可以一个 B 覆盖全部实现与检查；复杂工作才按有用边界分包，不预设数量。
轮内可以反复编码、查询、检查与修复，done 交回整个当前包，continue 留在同一包和会话。
详见[实现说明与验证](BEHAVIOR_COST_TOOLS.zh-CN.md)。
