# 图 3：目标能力补全与驱动翻译

位置：第三大阶段结尾。

## 可直接复制的 Prompt

绘制“从翻译方案到运行交付”的工程依赖流程图。横版 2:1，建议 2800×1400。
统一视觉要求：白底，深灰文字 #243444，辅助灰 #667788，分组使用淡蓝 #EAF1F7、淡青 #EDF5F2、淡灰 #F4F6F8；反馈线才使用低饱和橙色 #B57937。中文简体无衬线，类似思源黑体，标题与节点字号统一。规整矩形、细边框、直角连接线、充分留白，接近工程架构文档或论文插图。禁止机器人、人物、大脑、装饰芯片、照片、3D、渐变、阴影、霓虹、徽章、无依据的通过标记和百分比。不画宣传海报。只使用指定节点文字，箭头只表达指定关系。

从左到右四个区域。

第一区域是输入框“翻译方案”，内含“行为与接口映射”“测试约定”。

第二区域标题“准备目标能力”，上下两个框“复用已有接口”和“补齐必要接口”。输入框分别指向两框。“补齐必要接口”下用小字举例“I/O 端口、传统中断”。两个框汇合到“可用的目标框架接口”。这表示已有接口与新增接口共同构成目标框架，不是两套兼容执行路径。

第三区域标题“完成驱动翻译”，从上到下连接：“Rust 设备逻辑”→“所有权、并发与错误路径”→“组件与上层子系统集成”。第二组的“可用的目标框架接口”指向本组首框。

第四区域标题“运行交付”，从上到下连接：“构建当前制品”→“最小功能自测”→“公开运行验证”。第三组的集成框指向构建框。公开验证下面放输出条“代码 + 制品 + 分项证据”。

从“最小功能自测”画一条细橙色折线返回第三组外框，标“失败后定位与修复”。只表达实现阶段自测反馈，不将公开验证所有错误都返回驱动实现。不要绘制每个 Rust 语法细节或 shell 命令，不画机械的 C→Rust 逐字转换，不标“全部 PASS”。
