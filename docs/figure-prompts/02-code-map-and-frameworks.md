# 图 2：代码地图如何加速双方框架理解

位置：第二大阶段结尾，进入第三大阶段之前。

## 可直接复制的 Prompt

绘制“从代码地图到双方框架映射”的技术架构图。横版 16:10，建议 2560×1600。
统一视觉要求：白底，深灰文字 #243444，辅助灰 #667788，分组使用淡蓝 #EAF1F7、淡青 #EDF5F2、淡灰 #F4F6F8；反馈线才使用低饱和橙色 #B57937。中文简体无衬线，类似思源黑体，标题与节点字号统一。规整矩形、细边框、直角连接线、充分留白，接近工程架构文档或论文插图。禁止机器人、人物、大脑、装饰芯片、照片、3D、渐变、阴影、霓虹、徽章、无依据的通过标记和百分比。不画宣传海报。只使用指定节点文字，箭头只表达指定关系。

分四层，从上向下表达材料与分析的关系。

第一层是窄横框：“项目证据：来源代码｜目标代码｜设备资料”。

第二层是横向分组，标题“任务相关代码地图”，内部四个等宽小框：“驱动入口与共享核心”“构建配置与架构分支”“关键 API 与调用位置”“同类驱动完整链路”。第一层以箭头指向整个分组。其下小字“先定位，再按需读取原文”。不画整个仓库目录树，不画全量 AST 或完整调用图。

第三层左右并列两个分组，第二层分别指向它们。左组标题“理解来源框架”，内容四行：“设备生命周期”“寄存器与数据行为”“中断、锁与缓冲区”“错误处理与资源清理”。右组标题“理解目标框架”，内容四行：“注册与资源接口”“I/O 与 DMA 访问”“并发与上层数据通路”“安全边界与参考实现”。

第四层是两个分析组共同指向的宽框，标题“形成翻译方案”。内部三个并列标签：“直接复用”“接口适配”“能力补全”；底部短句“行为要求 + 接口映射 + 测试约定”。

重点突出代码地图帮助定向阅读、双侧研究汇合为方案。不要画左右组之间复杂交叉线，不虚构具体文件路径，不加速度倍数，不添加“AI 已自动理解”的徽章。
