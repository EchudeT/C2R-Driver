# 图 5：按原因返修与有效结果复用

位置：成本与质量章节开头。

## 可直接复制的 Prompt

绘制局部返修图“修哪里，验证哪里”。横版 2:1，建议 2800×1400。
统一视觉要求：白底，深灰文字 #243444，辅助灰 #667788，分组使用淡蓝 #EAF1F7、淡青 #EDF5F2、淡灰 #F4F6F8；反馈线才使用低饱和橙色 #B57937。中文简体无衬线，类似思源黑体，标题与节点字号统一。规整矩形、细边框、直角连接线、充分留白，接近工程架构文档或论文插图。禁止机器人、人物、大脑、装饰芯片、照片、3D、渐变、阴影、霓虹、徽章、无依据的通过标记和百分比。不画宣传海报。只使用指定节点文字，箭头只表达指定关系。

上半部从左到右画五个主流程矩形，依次用箭头连接：“对象与材料”“框架研究与方案”“驱动实现”“制品准备”“运行验证”。前两个节点放在浅灰分组内，标“未受影响的分析结果保留”。这只表示常见交付期修复，不表示上游设计永远不能修改。

下半部画一个分流框“根据实际失败归因”，从“运行验证”向下连到分流框。由分流框引出三个独立的原因分支，各自通过橙色折线连接上方对应节点：
“源码或集成缺陷”→“驱动实现”；
“镜像或启动入口问题”→“制品准备”；
“测试脚本或判据问题”→“运行验证”。

三条反馈线走独立通道，避免交叉。它们是按原因选择，不是必须同时执行的三个步骤。

底部说明带写两句：“相关实质输入未变：复用有效结果”“仅报告文字调整：不重跑整轮实验”。右下小字“失败记录保留，修复后验证受影响部分”。

不要把所有错误都连回第一个阶段，不画无条件全流程循环。不要添加节费比例、提速倍数、钱币、仪表盘或“全程无需人工”的字样。图解释降低重复成本的方法，不表现量化收益。

## 图注

图 5　根据问题归属修复实现、制品或测试入口，保留未受影响的工作；减少重复执行，而不是减少必要验证。
