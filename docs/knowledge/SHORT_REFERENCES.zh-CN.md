# 模型短引用与控制器完整身份

模型负责选择原文、解释语义和提交文件；控制器负责计算、保存和核对身份。
本改动不增加模型回合、阶段或审查，也不改变已有验收条件。

## 使用接口

控制器启动工作者时绑定 `DPF_WORKER_PROJECT`、`DPF_WORKER_JOB` 和
`DPF_WORKER_STAGE`。新会话及续跑都使用本次 job 的绑定。

| 场景 | 模型提供 | 控制器处理 |
| --- | --- | --- |
| 提交产物 | 文件路径、类型、决定 | 自动取得 job，计算文件哈希、保存完整收据 |
| 知识查询与任务上下文 | 问题或原文路径 | 用 `evidence_ref` 替换结构化哈希、CAS 元数据 |
| 读取证据 | `--ref R12ab34cd-7` | 还原路径及完整哈希，读取前核对内容 |
| 继续读取 | `--cursor R12ab34cd-8` | 恢复路径、行列、筛选条件及内容身份；可调整 budget |
| 目标知识引用 | 短引用和原文行号 | 提交时核对当前索引并冻结完整 citation |
| 人工审计 | 查询短引用 | 显示原始完整元数据 |

例子中的引用仅演示格式；实际引用由控制器分配，模型不能自行编造。
在已有工作者环境中：

```sh
python -m driver_port_factory.read_evidence --path /absolute/path/source.rs --contains try_lock
python -m driver_port_factory.read_evidence --cursor R12ab34cd-8
python -m driver_port_factory.short_refs R12ab34cd-7
```

使用 `tool_runtime` 给出的 Python 路径和命令。人工查看时可用
`python -m driver_port_factory.short_refs REF --project RUN`；读取工具的
`--full-provenance` 可显示完整身份。普通非工作者知识 CLI 保留原始输出，
现有控制器 API 与机器产物仍使用完整哈希。

`--ref` 读取要求引用同时包含本地文件位置和完整内容身份。共享库搜索等仅包含
条目/快照元数据的引用用于引用与审计，不能直接当作本地文件游标；需要时先查看
元数据，再按已有共享库接口读取或导入原文。

目标研究的 `.probes.json` 支持以下 citation：

```json
{"evidence": "R12ab34cd-7", "line_start": 20, "line_end": 28}
```

提交收据中保存解析后的 `chunk_id`，后续查询重放、行号检查和原文哈希检查
继续执行，不依赖模型再次抄写短引用。该格式仅用于已支持的目标研究 citation，
不是替代任意 JSON schema 的通用占位符。

## 身份和失败边界

- `.dpf/references.sqlite3` 保存工作区命名空间和只追加的引用映射；相同对象复用引用。
  原文或版本变化产生新引用，不把旧引用重新指向新内容。
- 引用不是截短的 SHA256。完整身份保存在映射、CAS 和原有收据中。
- 其他工作区的引用、错误引用类型、缺失或损坏的映射会报错。
  文件内容变化返回 `CONTENT_CHANGED`；目标研究引用过期拒绝提交。
- 游标保留原查询，不能通过追加新查询或另一个路径改变其含义。
- 工作者提交和实验命令拒绝覆盖绑定的 job 或工作区；提交还检查 stage。
  人工命令可继续显式传入 job。
- 本地注册表帮助防止误关联，不构成对恶意工作者的权限隔离或独立可信证明。
  短引用也不证明模型读过原文或理解正确。

只转换已识别的结构化元数据；不改写源码、原文或日志里的字符串，不屏蔽
实际需要模型选择的版本标签。原始收据、人工审计输出和部分其他工具仍可能
显示长身份；这些身份无需复制进模型报告。

## 验证与实验边界

离线回归覆盖并发分配、工作区隔离、文件变化、Unicode 长行分页、提示上下文
短化、初始及续跑 job 绑定，以及短 citation 提交后冻结并通过原有目标研究门禁。
这些是合成控制器测试，不是实际驱动翻译质量或成本收益证明。

本轮仅修改开发仓库。已冻结的 pvpanic 实验使用自己的 controller 副本，
保持原协议运行；下次实验才采用新接口。具体节省的 token、费用与时间需用
相同条件的真实运行测量，不能由引用字符串变短直接推导。

## 文件系统短路径

新项目默认 `compact_paths=true`，不再把完整仓库标识和 commit 拼进工作目录名：

| 用途 | 首个目录 |
|---|---|
| 可写目标工程 | `work/target` |
| 冻结源代码 | `.dpf/worktrees/source` |
| 冻结目标基线 | `.dpf/worktrees/target` |
| 冻结 QEMU 基线 | `.dpf/worktrees/qemu` |

控制器在 `.dpf/paths.sqlite3` 中保存追加式身份映射。相同仓库/commit 续跑仍使用同一路径；
改变版本则分配 `target-2` 等新路径，不覆盖或重命名先前的工程。Git commit、tree、来源 URL、
lock 及命令证据仍完整记录，获取与恢复时继续核验；短路径不是版本身份。

向模型展示 CAS 证据路径时，提供 `.dpf/e/E15` 这类真实可读取入口，`cat`、`rg` 或
`read_evidence` 可以直接使用。它是不可变 CAS 文件的符号链接，完整内容身份留在原引用表。
同一内容保持同一入口，内容变化创建新入口；已有入口若被改指向会拒绝使用。
原 CAS 与运行收据不改名。`E15` 是任务内文件入口，不是契约编号，也不是通过状态。
模型输出正文或命令日志中已经写出的长路径不会被追溯重写。

历史配置没有 `compact_paths` 时解释为 false。当前冻结实验继续原目录和引用，不能在运行中
批量重命名。项目根目录由启动时的 RUN 参数决定，仍可由操作者选择简短目录名。
