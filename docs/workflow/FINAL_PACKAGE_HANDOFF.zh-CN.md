# 最后工作包与最终整组验收

实验09暴露了两个浪费：分析自行把额外内核测试写成必交任务；实现完成后固定开启交付自查，
重新研究、改代码、重跑。此外，临时PATH变化使同版本通过记录不能复用。
开发版取消固定模型收尾回合和新增done门禁；不能用另一个复杂审核代替它们。

## 正常流程

1. 分析围绕预置测试和源行为义务设计完整工作包，不自行增加必交ktest、mock或故障注入。
2. 实现、自查和必要检查留在当前工作包、原会话中；已有开发测试结果保留，不为记录格式重复执行。
3. 最后done附简短说明直接交付，控制器捕获实现，14登记产物。
4. **15对同一个最终版本完整运行预置测试一次。pvpanic即三个测例都实际执行，不复用开发单项PASS。**
5. 同一批三个测例全部通过就结束，不追加模型审核、确认报告或第二轮测试。
   若真正失败，反馈具体失败并修复，保留失败记录；不能从其他版本借一个PASS补齐最终结果。

## “同一个版本”的含义

最终版本是14已经登记的构建产物和对应驱动代码快照。三项测试使用同一产物；控制器记录同一批次
并核对运行期间没有换代码或镜像。临时目录、会话ID、PATH前缀、日志输出路径和报告文字
不是驱动版本，也不参与已通过最终批次的复测判断。

控制器恢复或重复处理15时，有这个最终候选的完整通过批次就使用原记录，不再启动测试。
开发阶段的历史通过结果与最终完整批次分开标记；不同时间、不同版本的单项PASS不能拼成最终通过。

源行为范围不随测试覆盖缩小。公开测试未观察到的义务由实现回合给出有界源码论证与验证限制；
一般覆盖不足不产生新增测试任务或返工。真实缺陷照常处理。这里没有新增语义关键词门禁。
