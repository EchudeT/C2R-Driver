# 单次调用的问题材料包

## 目的与入口

把同一问题涉及的契约、C 源码、目标接口和测试依据放在同一次工具返回中。模型不必分别搜索四个来源再拼包。材料组织不调用模型，不生成另一份分析报告，不创建验收关卡，也不自动对每个函数运行。

入口已加入高费用阶段的 `tool_runtime.problem_packet`；详细用法仍在按需工具说明中，不把材料正文自动塞入所有提示。示例：

```bash
PYTHONPATH=src .venv/bin/python -m driver_port_factory.cli knowledge packet RUN \
  --question 'C-RX e1000_clean_rx_irq 接收长度和错误描述符如何处理？' \
  --contract-id C-RX
```

返回四组带出处的原文：`obligations`、`source`、`target`、`test`。契约中的验收断言也属于 `obligations`；没有命中的源测试文件，不意味着没有验收要求。

如果已经知道两侧名称不同，可以在**同一次调用**传 `--source-query`、`--target-query`、`--test-query` 或 `--obligations-query`，无需先调用工具学习另一个调用协议。显式 query 覆盖该组自动扩展，不会在未命中后偷偷扩大到全库泛搜。

## 内部怎样组织

1. 同一次请求加载并校验一份知识索引，各组共享这份快照。读取已 PASS 的契约与测试矩阵 CAS；同一报告承担两个角色时，只校验和读取一次。
2. 按问题中的标识符或显式契约 ID 定位相关原文。契约表格只取命中行，不把相邻契约的符号混入当前问题。
3. 从契约片段提取明确写出的代码名与文件行号，做至多一层定位。支持 `RxBuffer<FromDevice>` 这样的类型写法；省略文件名的裸行号不猜测出处，同名文件引用存在歧义也不猜测。
4. 代码结果优先排列函数或类型定义的文本特征，而非同名声明。这是定义定位启发式，不是 AST 或语义等价证明。已给定义后，不再用同名声明填第二个片段。
5. 为避免索引切块让函数体断裂，内部最多拼接一个同文件、同版本、出处一致的相邻块，校验重叠行。此过程不需要模型再调用 `show`。片段带原始行列位置、SHA256、版本、出处和必要的续读位置。
6. 同内容、同来源的索引别名合并正文、保留别名；不同版本或不同来源不合并。来源之间轮流分配输出，避免源代码占满预算而目标接口消失。

定义查找、同名声明去重和相邻块拼接都不是强制翻译条件。知识原文或 CAS 完整性失败时仍明确报错，不能把损坏数据伪装成“没有命中”。

## 质量、并发与成本的取舍

默认整个 JSON 输出最多 **12,000 UTF-8 bytes**，包括元数据；可设 4,096–24,000。每组最多两个片段，按有命中的组分配预算，不固定把代码切成十几行的小碎片。预算不足或没有匹配都有明确状态，截断也可辨认，不宣称材料完整。

这里只做本地读与检索，共享校验和一次返回比“让模型并行启动四个检索，再多轮归并”更直接。没有新增子模型、模型汇总、并行审查或全库索引构建。独立问题仍可以由调用方并发查询，但不默认批量生成一堆当前用不到的材料。

需要继续查看复杂函数或其他机制时可以按出处扩读；不承诺任意问题都能在固定字节数内完全解释。但常见的契约→源码→接口联取，以及跨索引块的局部上下文，应尽量在一次返回中完成。

## 已知边界

- 这是文字、标识符和明确引用驱动的材料组织，不是自然语言语义搜索或自动 API 映射。携带契约 ID、函数名或类型名的问题效果更可靠。纯自然语言没有定位线索时，不用无关背景填满输出。
- 目标组来自冻结知识材料，不代表当前已经修改过的目标工作树；判断当前实现状态仍需读正在编辑的源码。
- 默认组织这四类材料；没有默认扫描硬件手册、QEMU、工具链等所有领域。专门的硬件/模型问题仍可用已有定向检索工具。
- 不递归展开调用图，不推断测试 oracle，不证明语义等价，不将缺失命中变成迁移缺陷。
- 单次返回更少、检索更快，不等于已经证明真实模型总费用下降。

## 只读历史试取

对历史成功 E1000 项目做了两次只读试取，没有改历史状态或调用模型，记录在 [离线试取数据](audits/problem-packet-retrieval-2026-09-27.json)。

- RX 问题：8,224 bytes，约 0.108 秒。返回契约 C-RX、`e1000_clean_rx_irq` 实现附近的原文、目标 `RxBuffer` 定义与接口；源测试组没有文字命中，未虚构测试。C 和 Rust 两侧均在工具内拼接了相邻索引块。
- 边界问题：8,859 bytes，约 0.064 秒。由契约中的明确文件行号定位到两段 C 实现；没有足够定位线索的目标和测试组留空。

第一次试取暴露了同名声明先于实现的问题，已在实现中修正。该记录展示检索内容与体积，不是代表性性能基准、翻译质量评估或账单对照。

覆盖单次跨来源联取、总 UTF-8 字节预算、不同组公平分配、显式查询覆盖、不填无关背景、长行行列定位、只展开一层、CAS 共享报告去重、单次索引校验与损坏传播、别名与不同版本保留、表格契约隔离、泛型类型提取、明确引用与同名歧义、定义优先、相邻块内部拼接。
