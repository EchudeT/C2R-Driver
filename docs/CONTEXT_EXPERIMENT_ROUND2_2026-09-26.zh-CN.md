# 第二轮实验：先核实预算约束，再分离上下文与知识因素

## 已执行实验

上一轮中转返回的 `max_output_tokens` 为 null，无法确认限额。本轮做一次小输入探针：同一模型 `gpt-5.6-sol`，low reasoning，请求输出整数 1 到 200，同时显式设置 `max_output_tokens=64`。不开放工具，不恢复驱动会话。

实际结果：usage.output_tokens **403**，status completed，返回上限仍为 null。请求上限没有被遵守。这比“字段未回显”更强：在这次请求中有明确的超限观测。不能因此推断所有中转或所有模型都如此。

该次公开费率估算 **$0.008296**；加上首轮 $0.5507184，累计已知估算 **$0.5590144**。这是仓库费率估算，不是中转账单。本轮没有继续付费调用。原始请求、流式事件、响应、metrics 和评阅见 [限额探针](experiments/context-cap-probe-2026-09-26/)。原 metrics 按当时执行器保留；后续 assessment 将结果分类为实际超限。

官方 Responses 文档定义 max_output_tokens 为包括可见输出及 reasoning 在内的生成 token 上限：[Create a response](https://developers.openai.com/api/reference/resources/responses/methods/create)。本轮核对该定义，没有通过更换未知 provider 或隐藏重试绕过观测。

关闭客户端连接、墙钟超时不能证明服务端停止生成或计费。因此不以客户端截断代替预算约束。当前 20 美元授权保持不变；但该通道不具备已验证的请求输出限额，不展开批量迁移或实验。

所有组都获得同一条旧 collector 归因和当前反证，避免首轮“要求交接组纠正没有提供给它的旧说法”的问题。机制证据包含源 IRQ 注册、QEMU INTA 信号、目标可选 MSI-X API 的原始摘录，不附带标准答案。它不证明目标整体缺少 INTx。

每组预定两次、两个反向顺序区组，合计 8 次。dry-run 估算预留 $6.272832。为了保守累计，将旧实验全部预留 $4.644624 和本次探针预留 $0.03892 都扣除，20 美元中剩余可预留额设为 $15.316456，未用已知费用替换旧预留。估算仍不能约束未知中转加价。

## 本轮代码优化

1. 实验执行器支持协议声明每组材料清单，便于控制因素，未知组名不再默默回退为交接组。
2. 检查实际 output_tokens 是否超过请求值，优先记录 provider_exceeded_output_cap；同时检查 served model 与请求模型身份。未回显上限继续记为未知，不能宣称合规。
3. 拒绝 NaN、无穷和非正预算。既有失败、未知费用或 stop_reason 会阻止后续不同调用；同一已有调用不自动重试。协议锁定在直接 run_call 和 CLI 两层均有效。
4. `input_changes` 现在遍历嵌套列表。此前只递归字典，因此数组内的 CAS 引用没有进入变化提示；修复后可标记 new/changed/unchanged，减少 worker 对已提供证据的重复调查。

第 4 项是控制器的信息提示修复，不直接删减 prompt，不证明模型已读文件，也不承诺 token 节省。列表索引作为位置身份，重排保守地标记 changed，不误称相同。保留全部证据，验收标准、默认上下文策略及历史运行状态不变。

## 验证与下一步

新增离线用例覆盖实际超限优先级、非法预算、前次失败阻止新调用、材料按组选择、协议禁止执行、嵌套列表与重排引用。它们验证程序行为，不能替代 provider 真正执行限额的实验。

下一步有两条可并行推进的研究路线：

- 离线继续核实设备机制和目标平台适配证据，优先消除会让模型走错路线的知识缺口。
- 在有明确输出限额和可核对计费的执行通道上运行已准备的四组实验，再选择是否值得做原生会话的可执行修复对照。

不以花满预算或不断追加诊断调用作为进展标准。本轮的新证据是限额探针的实际失败；尚无新的上下文质量或驱动成功率结果。

最终验证：全量 **98 passed（91.16 秒）**；修改的实验脚本与新增/修改测试 Ruff 通过，git diff --check 通过。协议阻止执行的 CLI 检查在访问 provider 前退出，确认没有产生任何四组实验 call 文件。首轮原始实验产物哈希保持不变。
