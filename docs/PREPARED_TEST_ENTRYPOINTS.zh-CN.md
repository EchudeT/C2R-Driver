# 提前提供开发与公开验收入口

新任务在托管平台基线验证完成时，由控制器生成：

- `.dpf-output/implementation-smoke.sh`
- `.dpf-output/public-qemu.sh`
- 原有的 `check-presence.sh`、构建/格式化/运行单个用例入口。

模型不再为这两个入口编写调用包装或重新实现 QMP/串口传输。对于尚无预置测试的驱动，仍须根据冻结义务编写设备刺激和断言。
新的 pvpanic 全范围任务已由控制器[预置公开场景和断言](PREPARED_PUBLIC_TESTS.zh-CN.md)，
模型只适配接口并运行，不重写这些用例。通用运行工具与设备专属测试资产分别维护。

## 使用方式

在当前实现工作包内，通过已有 `driver_checks.platform` 登记一个必要用例：

```json
{"action":"register_case","id":"device-event","contracts":["C1","C2"],
 "case":{"devices":["<设备及参数>"],"timeout_seconds":60,
         "steps":[{"expect_event":{"event":"<预期事件>"}}]}}
```

`case` 也可以是当前目标工作树中已有的 JSON 文件路径。此示例仅说明格式；实际用例必须包含
所需初始化、刺激和区分性断言，不能把等待任意事件当作完整驱动验收。

工具保存用例、生成对应包装脚本，更新原有 `.dpf-output/experiments.json` 清单，返回
`REGISTERED_NOT_EXECUTED`。同一 ID 可更新用例，其他 ID 保留。模型不需手写该清单、包装脚本、
摘要或哈希；登记不是运行成功，也不自动证明契约覆盖。

然后调用 `driver_checks.check`：

```json
{"cases":["device-event"]}
```

这是当前工作包的开发检查。省略 `cases` 时执行完整已登记集合。当前包的必要检查仍须在交回
done 前完成。一个用例可覆盖多个契约，一包可完成多个用例，不产生额外工作包或模型阶段。

临时 `platform run_case` 继续可用，不自动登记到最终集合，避免将调试失败或无关探测加入验收。
需要正式使用的现有临时用例，可以按返回路径登记，正文无需重写。

## 最终交付与执行复用

生成的两个入口消费同一份完整用例清单；实现结束时和公开验收时都不要求再包装一次。
控制器识别生成的 smoke 入口，将其与 public 入口导向已有的逐用例执行器。
开发阶段的逐用例检查与之后的捕获使用相同 ID、超时、制品和依赖规则。
源码、环境、制品、用例和相关依赖身份匹配且原始证据有效时，复用原收据；失败不复用为通过。
自动生成的独立用例绑定自身定义和公共 harness 文件，不因其他独立用例的登记或修改而重跑。
共享测试脚本/数据放在公共 harness 中，修改时影响相关用例；显式引用其他用例名称时也保留其输入绑定。
自定义脚本继续使用原有依赖规则。本工具不要求模型另外填写依赖表。

两个入口名称保留是为了接入现有交付接口，不代表必须启动两套重复模型或重复 QEMU。
它们也可由 shell 直接执行：逐个运行清单脚本，处理单用例超时，保存执行输出；不会递归调用
外层 experiment 捕获器，因此不会重复获取同一把实验锁。

空清单、缺失用例、脚本失败或超时不能产生套件成功。最终执行全部登记用例，不沿用最后一次
开发选择的子集；冻结范围是否被完整覆盖仍按已有契约和交付验收规则核对。
已有自定义入口不会被自动覆盖；自定义 smoke 继续走原有执行路径。
