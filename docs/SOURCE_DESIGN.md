# 源码理解与迁移设计：一个任务，按问题取证

## 当前决定

源码分析、迁移契约和公开测试计划合并为 `migration_contracts`：同一工作者读原始源码、解决疑点、完成设计与自检，交付一份 Markdown。控制器以契约和测试计划两个视图引用同一内容，不增加报告。

开发流程为 18 个阶段。第 12 步完成源码与设计，第 13 步独立分析审查，第 14 步单独补齐并封存目标框架能力，第 15 步实现，第 16 步包装，第 17 步公开 QEMU 与工作者自检，第 18 步由同一审查者核验最终功能与证据。分析审查在设计阶段封存前集中反馈全部问题，关键结论引用精确原文行号；参见 [分析审查](ANALYSIS_REVIEW.md)。此前的身份、采集、环境实验和目标平台研究保留，因为它们提供真实输入或运行证据。

## 工作原则

- 从已固定的驱动入口追踪共享核心、头文件、配置、回调和必要框架定义，不把单个文件当作完整行为。
- 直接阅读相关原文。只有具体语义疑点需要时，才运行最小范围的预处理、类型／布局、条件编译或调用目标探测。
- 复用现成编译配置和证据。不得仅为了通过阶段而编译源内核、生成完整 AST/CFG/CPG、查询索引或重述机器事实。
- 在现有报告记录有用的命令、观察、源码位置和它们支持的结论。未解决的行为不能靠名称、正则或猜测补齐。
- 编码前完成目标 API 映射、所有权／并发／生命周期设计，以及可执行的测试入口和 oracle。
- 实现自检、当前驱动身份验证、真实 QEMU 执行与失败记录不削减。

## 明确删除

`source_closure` 独立阶段、`SOURCE_ANALYSIS` 往返协议、全量结构化 C 导出与复建验收、语义 SQLite 导航、`knowledge c-facts`／`c-facts-build`、控制器 `--analyzer` 配置及这些能力的专用测试。它们不以旧版兼容或备用路径保留。

下游依赖迁移计划和原始材料，不依赖机器索引是否存在。QEMU 材料身份绑定到采集阶段的冻结材料清单。

## 与 Skill 的关系

保留 Skill 的源码覆盖、证据区分、目标研究、设计、自检和运行验证职责。用户明确授权将上游“必须全量结构化事实”替换为“针对具体问题按需验证”；统一工作协议显式说明此优先级，不能同时再要求全量索引作为过关条件。

## 证据与边界

audit-06 的两个语义索引合计约 63.7 MB；四个核心源码文件合计约 68 KB。工作者有查询，但不能据此证明节省了总阅读或实现成本。此次删除的是未经证实的强制前置成本，不保证某个固定费用降幅。

这是阶段协议变更，不提供旧工作流执行兼容。旧实验的 SQLite、CAS、代码、日志和报告保留；不要用新控制器直接续跑旧图，也不要将未完成的源码阶段自动算作设计通过。新协议端到端效果仍需新实验验证。
