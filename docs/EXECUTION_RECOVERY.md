# 执行与裁决协议

## 职责

Skill 定义实现要求，原工作者负责实现和功能自检。程序负责执行、记录真实结果、保存交付物和推进状态；程序诊断不是功能否决权。

所有开发阶段（含静态阶段）共用 `PortRunner._run_project` 的恢复入口，不使用错误文字白名单决定是否给工作者修复机会。

| 情况 | 处理 |
| --- | --- |
| 正常执行、有新证据 | 同一工作者继续或阶段完成，不增加审查调用 |
| 产物已经捕获，检查有争议 | 保存候选与诊断；工作者 ACCEPT、修复并直接提交正常交付物，或 BLOCKED |
| Git 传输失败 | 保存选择、已下载仓库及失败日志并暂停；恢复只重试未完成下载，不调用 AI 重选版本 |
| Git 下载失败且远程明确不存在所选 tag | 仅失败后查询远程引用；确认缺失后交同一工作者更正选择，保留已下载资源 |
| 其他工具、输入、交付协议失败，产物尚未捕获 | 保存诊断；工作者修复当前阶段并提交正常交付物，或说明外部 BLOCKED |
| 模型调用不可用 | 保留待处理决定，暂停；不再次调用模型处理模型服务错误 |
| 账本、配置或 CAS 损坏 | 停止；不能通过模型判断改写不可变证据 |

ACCEPT 发布已有候选，并单独记录工作者判断，不把 FAIL 测试改成 PASS。`artifacts: null` 表示尚无完整候选，不能凭一句 ACCEPT 生成下游不存在的数据。

控制器按实际采集状态路由，不要求模型为路由改写答复：若 ACCEPT 对应的产物尚未采集，或采集后的修复输入已改变，复用该答复走正常阶段采集/检查；只有未变化的已采集候选才直接发布。原报告中的明确自检结论可以随附裁决说明保留，不凭 ACCEPT 推断自检通过。旧诊断保留作历史，新失败由本次采集产生，不继续围绕旧的空候选重复询问模型。

## 恢复与成本

执行失败与检查争议都写入 `.dpf/checker-decisions/`；控制器重启先处理待办决定。请求记录当前模型结果边界，边界之后已落盘的修复答复直接复用，不重复付费请求。修复答复就是正常交付物，不要求先提交重试决定再重复提交。静态阶段收到修复说明后直接重跑工具。已通过阶段不因工具错误自动回退。

恢复只在失败时比较上游输入和当前修复输入：交付阶段的源码差异、脚本、harness、运行镜像，
以及获取阶段的实际选择。不同输入不共用三次预算；仅报告改字不算执行进展。
同一输入反复修复三次仍失败会保存 PAUSED 请求；重启不清零，输入改变后重新处理当前阶段。
这只是防持续付费的粗粒度停滞保护，不声称能判断所有因果变化。

若变化发生在外部（例如恢复网络或安装工具），使用：

```sh
python -m driver_port_factory.cli stage recovery-resume RUN_DIR STAGE --reason '具体恢复原因'
```

该操作在账本记录原因、保留所有失败，不接受产物、不回退阶段；随后正常恢复 port。
`status` 显示 recovery=PAUSED/PENDING 和原始请求路径。

同一命令也可用于因 Git 传输错误暂停的 repository_acquisition，显式请求原工作者诊断
地址或版本选择。普通 port 恢复仍只重试下载，不额外调用模型。远程可访问但完整 commit
获取失败时直接交工作者诊断；未出现在引用列表不被程序认定为 commit 不存在。

提示词只在统一 prompt pack 描述职责与决策协议；实际错误、日志路径和原始产物放在 reference_material。工具返回失败不等于模型回答错误，也不要求模型为了满足收集器而修改正确实现。

## 本次暴露的缺陷

第十三步把 GCC 编译数据库交给 Clang 分析，后者不接受部分 GCC 参数。原控制器只将特定文字的提取错误交回工作者，目标探测错误却直接终止。新机制不猜测应删哪些编译参数，而把完整失败证据交回同一工作者，保留真实编译记录，在当前阶段修正分析输入。

## 验证边界

报告正文（含旧操作标记）是历史证据，最后一个非空行才是当前动作。执行、自检、
阻塞和裁决均使用同一结尾边界；返修目标取当前 REWORK 前一非空行，不扫描旧记录。
追加收尾不要求清理历史标记；已有成功执行仍按输入指纹复用，不因报告追加重跑。

自动测试覆盖：任意工具诊断、执行异常、持久化恢复、模型离线不递归调用、缺少产物禁止虚假发布、静态阶段接受及失败原始记录保留。端到端运行仍需实际验证，单元测试通过不是全流程成功证明。
