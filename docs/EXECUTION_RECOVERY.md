# 执行与裁决协议

## 职责

Skill 定义实现要求，原工作者负责实现和功能自检。程序负责执行、记录真实结果、保存交付物和推进状态；程序诊断不是功能否决权。

所有开发阶段（含静态阶段）共用 `PortRunner._run_project` 的恢复入口，不使用错误文字白名单决定是否给工作者修复机会。

| 情况 | 处理 |
| --- | --- |
| 正常执行、有新证据 | 同一工作者继续或阶段完成，不增加审查调用 |
| 产物已经捕获，检查有争议 | 保存候选与诊断；工作者 ACCEPT、修复并直接提交正常交付物，或 BLOCKED |
| Git 下载失败 | 保存选择、已下载仓库及失败日志并暂停；恢复只重试未完成下载，不调用 AI 重选版本 |
| 其他工具、输入、交付协议失败，产物尚未捕获 | 保存诊断；工作者修复当前阶段并提交正常交付物，或说明外部 BLOCKED |
| 模型调用不可用 | 保留待处理决定，暂停；不再次调用模型处理模型服务错误 |
| 账本、配置或 CAS 损坏 | 停止；不能通过模型判断改写不可变证据 |

ACCEPT 发布已有候选，并单独记录工作者判断，不把 FAIL 测试改成 PASS。`artifacts: null` 表示尚无完整候选，不能凭一句 ACCEPT 生成下游不存在的数据。

## 恢复与成本

执行失败与检查争议都写入 `.dpf/checker-decisions/`；控制器重启先处理待办决定。请求记录当前模型结果边界，边界之后已落盘的修复答复直接复用，不重复付费请求。修复答复就是正常交付物，不要求先提交重试决定再重复提交。静态阶段收到修复说明后直接重跑工具。已通过阶段不因工具错误自动回退。

同一阶段在上游输入未变时，最多允许三次恢复请求；仍不能完成则暂停，重启不会清零预算。
这是防止持续付费的停止界限，不声称程序能判断所有代码因果变化。Git 下载错误和模型服务错误
直接保留状态退出，不开启模型错误修复对话。保留显式 ACCEPT 权限及原始失败记录。

提示词只在统一 prompt pack 描述职责与决策协议；实际错误、日志路径和原始产物放在 reference_material。工具返回失败不等于模型回答错误，也不要求模型为了满足收集器而修改正确实现。

## 本次暴露的缺陷

第十三步把 GCC 编译数据库交给 Clang 分析，后者不接受部分 GCC 参数。原控制器只将特定文字的提取错误交回工作者，目标探测错误却直接终止。新机制不猜测应删哪些编译参数，而把完整失败证据交回同一工作者，保留真实编译记录，在当前阶段修正分析输入。

## 验证边界

自动测试覆盖：任意工具诊断、执行异常、持久化恢复、模型离线不递归调用、缺少产物禁止虚假发布、静态阶段接受及失败原始记录保留。端到端运行仍需实际验证，单元测试通过不是全流程成功证明。
