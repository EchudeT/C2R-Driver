# FSE 论文：核心机制消融设计

方案记录日期：2026-10-15。本文记录已讨论确定的 A、B、C 替代方案，用于论文 RQ4。当前仅确定实验设计，不表示变体已实现、实验已启动或收益已得到验证；不改变既有冻结实验和生产流程。

## 1. 研究目的与论文位置

论文围绕三个机制展开：前置查证会改变设计的关键前提；显式组织源行为及目标承担关系；以工作包组织完整能力的连续实施。

主评价采用四个 RQ：

| RQ | 问题 | 主要证据 |
| --- | --- | --- |
| RQ1：迁移有效性 | 相较通用 agent，能否交付可运行的完整驱动服务？ | 全任务的最终公开验收。 |
| RQ2：源行为保持 | 在公开测试之外，对源代码所规定行为的保持情况如何？ | 模型不可见的输入变种与行为场景，按实际覆盖范围报告。 |
| RQ3：返工与交付效率 | 问题发现时点、修正范围和总投入有何差异？ | 时间、token、费用，以及少量按统一规则核对的过程案例。 |
| RQ4：核心机制贡献 | 三项机制分别如何影响行为表现与交付投入？ | 本文规定的受控替代实验。 |

消融用可正常解决任务的传统方法替代完整机制，不靠禁止调查、隐藏源码或降低预算制造弱对照。每个变体分别从完整 Factory 派生，不累计删除机制。

## 2. 四组配置

| 组别 | 规划方式 | 实现指导 | 实施组织 |
| --- | --- | --- | --- |
| Full：完整 Factory | 关键前提前置查验 | 显式源行为责任与目标映射 | 工作包投递、调度及进度协调。 |
| A：经典规划 | 常规计划；出现问题先修改计划，再修改代码 | 保留显式语义责任 | 保留工作包组织。 |
| B：功能指导 | 保留关键前提前置查验 | 功能级指导，不系统建立条件化语义责任 | 保留工作包组织。 |
| C：分析实现一体化 | 保留关键前提前置查验 | 保留显式语义责任 | 分析者在原会话直接完成实现，无工作包和独立实现工作者。 |

三类模块存在协作关系。单项替代测量的是该机制在完整系统中的增量，不假定各机制完全独立，也不由单项差值推断所有交互效应。

## 3. A：经典计划替代前置设计查验

### 替代流程

1. 阅读完整源／目标代码，形成常规迁移计划。
2. 按计划实现，允许源码查询、构建、运行及调试。
3. 出现事实与计划冲突时，先修订相关计划，再修改代码。
4. 完成后进入共同的最终验收。

### 移除与保留

移除关键前提 P 的专门识别、提前查证、支持依据校验，以及相关前提向实施投递的机制。不要求分析者系统回答“哪些事实的不同答案会推翻当前设计”，不把这些专门查验设为进入实现的条件。

保留一般计划、显式源行为 C、目标路线 R、工作包 B、正常计划修订和独立验收。计划需要表达当前接入和实现方向，但不必模拟完整方法的 P 表示。不能因该变体不产生 P 而继续用完整版本的 P 校验拒绝它。

模型可以自行提前检查锁、权限、接口和设备条件，也可以在实现时发现问题；不得禁止这些正常行为。自然出现的提前查证如实记录，它表明常规规划本身也可能产生同类行为。

### 检验问题

专门组织前置设计查验，相较经典的计划—执行—反馈—修订，是否改善设计问题发现时点、减少后期重做，并值得其分析投入？

## 4. B：功能对齐替代显式语义对齐

### 替代流程

1. 从冻结范围和源代码形成需要实现的功能能力清单。
2. 为这些能力确定目标接入方案、关键前提及工作包。
3. 工作者依据功能目标自主读取代码、实现、自查和修复。
4. 使用与完整方法相同的公开验收和非公开评分。

### 移除与保留

移除显式源行为义务 C 的系统提取、条件化源—目标责任映射、与工作包的关联，以及实施时对这些责任的直接投递。不额外要求建立“源触发条件—要求结果—目标承担方—成立前提”的语义责任表示。

保留功能级要求、目标路线、关键前提、完整工作包、源码访问和一般语义保持要求。功能说明、实现计划及必要的资源与生命周期处理仍然正常存在；不能让原 C 关联检查成为该变体的错误门槛。

| 保留的功能指导 | 不再系统提取、映射和投递的语义责任示例 |
| --- | --- |
| RNG 支持阻塞与非阻塞读取 | 驱动与共享调用者分别承担的缓存、补充时机和错误映射。 |
| NVMe 支持读、写、刷新和恢复 | 重试期间的数据保持、所有权与完成责任。 |
| 网卡支持收发及停止／启动 | 各执行上下文的共享状态约束和停止后回调、资源存活条件。 |

外部任务范围不变。属于功能定义本身的条件仍须说明，例如非阻塞操作不能被写成允许无限等待。模型可以自主分析语义，发现并维护相关条件；消融移除的是工作流的显式语义组织，不是模型能力或实际行为要求。

关键前提 P 仍可核对会改变接入和实现的目标事实，例如接口访问权限、执行上下文和设备配置，但不能通过另一套提示重新生成完整 C 责任清单。两者有语义交集，因此不能将本变体解释为“完全没有语义推理”。

### 检验问题

一般功能指导和模型自主判断是否已经足够？显式语义责任组织是否进一步改善非公开行为表现、减少遗漏并影响总投入？

## 5. C：分析者在原会话直接完成实现

这是已选定的 C 方案，取代此前讨论的阶段交接、强制切换会话或仅修改上下文长度的方案。

### 替代流程

1. 分析者正常完成源行为 C、目标路线 R、关键前提 P 的分析与必要查证。
2. 不生成 B 工作包，不进行分析者到独立实现工作者的交接。
3. 分析者在同一会话继续修改代码、适配框架、构建、运行和修复，自主决定分解方式及推进顺序。
4. 出现新事实时直接修订分析／计划与相关代码，保留出处和实际执行记录。
5. 提交最终候选，由共同的外部验收器执行完整公开套件，再进行非公开评分。

### 移除与保留

移除 B 工作包生成、包间依赖编排、控制器当前包选择、包级 continue／done、相关上下文投递和包级进度协调。不先生成工作包再绕开执行；也不以重命名的步骤索引继续维持同一套包级控制。

保留完整分析及原始材料、持续会话、同等构建／调试能力、一般计划调整和独立验收。模型可以自行列待办或分解任务，程序不再将其编译为受控工作包。分析、连续实现、最终验收仍是三个宏观阶段，阶段不等于必须新开模型会话。

分析者进入实现时应具备与正常实现者相同的源码修改和工具权限，不能因为原分析角色的权限限制导致假失败。最终运行记录和验收裁定仍由程序保存，分析者不能自行批准交付。

### 检验问题与归因边界

已经完成分析的模型直接继续实现是否足够？工作包、角色交接、上下文投递及进度协调组成的实施组织还能提供什么增量？

C 同时去除工作包组织和分析—实现交接，结果归于这一组合组织策略。不能将差异单独归因于包数、某种依赖算法或上下文长度。原会话包含分析者已形成的上下文，这是该替代方法的自然优势，不人为消除。

C 与外部 Codex 基线不同：C 保留 Factory 的分析机制及执行工具；外部基线自行组织完整迁移过程。因此 C 更适合回答实施组织在分析之外的增量。

## 6. 共同条件与实施边界

1. 固定完整 Linux、目标基线、设备配置、任务范围、Docker／QEMU 路线及测试版本。
2. 固定底层模型、推理强度、总预算和停止规则。分析、实现、修订及失败调用的投入全部计入；C 不因复用分析者而免计分析费用。
3. 所有组保留相同能力的公共执行工具。只去除被研究机制专属的规划、投递和进度接口；不得连带移除构建、日志或调试能力。
4. 不额外强制探测、报告、模型审阅、阶段检查或重复测试，不用新增负担制造组间差异。
5. 外部共享经验的初始条件一致并冻结。各任务自身形成的信息可以演进，不在实验组间即时回流。知识库暂不单独消融，也不声称知识路径是独立不变因素：B 会减少语义分析产物，C 会减少工作包派生产物，这些属于相应处理。
6. 最终验收使用同一最终候选的完整公开集合；非公开反馈不进入实现修复。内核夹具评分需要重新构建时，只允许规定的测试变动并核对候选实现保持封存。
7. 检查各变体的实际提示、工具暴露和控制路径，既不能保留已移除机制的错误校验，也不能由备用路径偷偷恢复同一机制。正常自主调查不属于违规。
8. 变体在独立实验配置中实现，不覆盖历史冻结版本，不修改既有候选或成绩。本文不表示已经存在可运行开关。

## 7. 任务、重复与指标

消融只覆盖少量代表性任务，无需复制全驱动×全模型的主实验矩阵。RNG、NE2000、NVMe 是优先候选：分别涉及跨调用者责任、平台／中断前提，以及协议边界与请求资源。若论文强调复杂多包协调，可加入已有真实多包计划的 IGB；单包任务不能证明复杂包间依赖处理的收益。

具体任务、模型及重复次数在启动前冻结，按机制覆盖选择，不按已知胜负挑选。建议一个模型、三个驱动、每组三次独立翻译：三个消融共 27 次；Full 的 9 个位置只有在方法版本、环境、预算和评价协议匹配时才能复用已有记录，否则补齐。此规模是建议，尚非已安排的运行队列。

| 评价维度 | 指标与使用范围 |
| --- | --- |
| 迁移有效性 | 任务完整成功、构建、初始化与最终公开验收。 |
| 源行为表现 | 非公开 A/B 与补充行为测试分别报告；不将公开成绩混入非公开成绩。 |
| 效率 | 分析及实现总费用、时长、缓存／非缓存输入、输出 token 和请求数。 |
| 过程解释 | 按统一规则核对设计决定、反证和实际修改；区别普通开发修正与推翻已有设计的返工。 |

保留全部尝试、失败、超时、环境故障及重跑身份。不能选择表现较好的三次代替预定重复。少量过程案例用于解释差异，没有完整标注就不推算全体返工发生率。测试结果和模型波动按任务及重复报告，不预设完整 Factory 必须胜出。
