对齐基准：`V01dMur10c/C-kernel-to-Rust` 提交
`6a75e6e98075690fa74e6cc2f2216a2a9510ba60`（2026-09-18 获取）。
该版本只有入口和迁移两个 Skill；本项目已有的盲测模块不是这次开发者实跑的验证范围。

## 分工

默认交付标准是功能正确、必要安全保证成立、必需验证通过。命名、函数长度、模块
布局、结构美化等偏好不构成返工理由，不为清空建议启动非功能性整改。工具强制的
编译/检查错误做最小修复；已经完成的结构调整不为风格再次撤销重做。

优先级为稳定、正确完成第一，低成本第二。工作者与检查者共享模板中的验收标准，
包括行为/集成、生命周期/错误清理、测试证据及各阶段交付边界。审查必须引用具体
依据和失败后果；不得临时增加无关要求。检查者显式收到与实现者相同的测试计划。
实现前沿实际调用链核对执行上下文、抢占/锁、资源回滚及调度/期限语义；核心测试
不能替代适配层检查。反馈用自然语言说明触发序列、不变量、后果、代码依据和验证
判定，区分缺陷、疑问与建议。返工覆盖受影响的调用者和失败出口，并提供针对旧
故障的最小回归；已关闭项仅在新变更或证据出现时重开，并解释原因。不增加表格。

审查不是单向下命令：阻断项须证明约定设备/配置中可达的故障，或本阶段明确必需
但未满足的要求。检查者须先核对调用方、框架初始化、资源释放和基线保证；静态
因果证据可以成立，无须强求危险故障实跑，但未经证实的前提不算缺陷。工作者可
用原始源码和检查结果反驳，检查者必须明确撤销、缩小或补证，不能循环复述。
可选建议、范围外通用化、无明确后果的性能担忧、后续阶段验证不阻断。没有有据的
本阶段阻断项即 PASS；必要安全保证和约定的必需验证不降低。对话留在现有 Markdown
及会话中，不增加辩论模型、审批关卡或机器表格。

审查职责只分配一次：实现后的合规审查归 `target_compliance`，最终公开运行证据审查
归 `public_repair`。工作者正常自检并执行受影响测试，不额外启动可选的多角色审查
流水线。目标仓库的编码规则仍须遵守；适用的仓库审查 Skill 在指定审查节点执行，
不因可用或可选触发而变成工作者与审查者各做一次的额外门禁。若仓库明确要求交接前
的独立检查，则只执行该必需检查并交付证据。复审检查修复及受影响路径，保留未改变
部分的已有结论；不以“建议清零”为目标反复全量审查。新增跨路径影响仍须追查。

首次审查须覆盖完整的约定实现范围及本阶段适用要求，收齐必需检查结果、核实前提，
按根因合并成一批可执行反馈，不能发现第一个问题就退回，留下可检查区域到下轮。
工作者按整批意见修复或给出反证。复审新增阻断项须注明是修复引入、变更路径/新证据
暴露，还是此前漏检；漏检应明确承认，不得包装成新要求。覆盖及真实不可检查部分
在普通报告中简述，不增加表格，也不因追求一次反馈而隐藏后来发现的真实缺陷。

模型选择证据、研究目标、编写标准 compile_commands.json、迁移代码和测试、
编写构建/检查脚本及 Markdown。程序维护阶段状态、Git/文件快照、哈希、
结构化 C 分析和实际执行日志。阶段是证据门，不要求每个阶段都启动一个模型。
知识库构建、handoff、结构化分析、最终记录汇总直接执行。

默认目标统一放在 `data/prompt-packs/default/manifest.json`，`port run` 与
`codex run` 使用同一交付方式。环境、研究、合同、测试、实现、构建、运行和返工
均可交付自然 Markdown；采集的必要机器输入保留紧凑结构。审查只额外要求一个
`DPF_REVIEW: PASS` 或 `DPF_REVIEW: REWORK` 结论行，用于路由。

检查者单独阅读实际代码与原始证据，不能用实现者的报告冒充独立检查。
检查失败重开实现及后续门禁，把审查文件路径交回原实现会话。
运行修复也必须重新经过快照、目标检查、产物身份和公开验证。
运行失败直接路由回原实现会话，不额外启动一个“修复模型”再让实现模型接手。
公开脚本成功后，由原独立检查会话复核产物、判定器和实际日志。兼容阶段名
`public_repair` 现在承担失败路由/最终证据复核；没有独立的修复执行链。
最终复核要求 `DPF_REVIEW: PASS`，完整报告随控制器结果冻结，不能只凭 QEMU 进程成功收尾。
实现阶段允许必要的编译和局部测试，后续包装复用通过的结果。

## 静态分析的职责边界

编译输入、源码哈希、布局对应关系和证据完整性仍然是硬检查。
Linux 宏可能产生位置、字段和布局都相同的多个匿名结构体，解析器保留
Clang 的重复输出，按 AST 定义逐一绑定；布局有实质歧义时仍拒绝。

Clang 18 的 AnalysisConsumer 会跳过 `__inline` 前缀函数的 CFG。
工具以 `unavailable_functions` 明确列出这些函数，保留其 AST 正文；其他
无解释的 CFG 缺失仍拒绝。闭包外的平台回调保留为未解析的间接调用，
不伪造目标、不强迫模型补齐整个内核。`READY` 仅表示结构化证据可用；
实现和独立检查必须核查与驱动行为相关的缺口。

公开运行使用独立尝试目录，只认可成功的 QEMU exec 和本次产生/更新的日志。
这些机械检查证明执行边界，具体驱动行为仍由公开测试及证据审查证明。

## 上下文与恢复

- `.dpf/codex/sessions/` 保存会话标识和已读 Skill 摘要。
- 开发者流程的研究、环境、契约、测试设计、实现、构建和公开运行共用一个工作会话；
  合规/最终审查共用另一个独立会话，不默认启动 persona 子代理。盲测角色隔离不改变。
  阶段门禁仍然分别留证，但不为每道门禁重新研究一次。
- 工作会话按项目、角色、后端、模型和 Codex 配置隔离；每个任务独立重算 cwd 和
  sandbox，并把当前执行边界交给模型。旧项目无新会话记录时继承本阶段原会话。
- 同一会话并发启动会立即报错，不等待或复制一个写入者；进程退出自动释放锁。
- 每个任务旁保存 `.metrics.json`：耗时、首次响应延迟、是否恢复、提示词字节数和
  CLI 原始用量。恢复会话的计数可能包含历史，不能直接相加当作账单。
- 返工不删除实现会话；进程重启仍可恢复。审查和实现不共用会话。
- CLI 启动会话时立即保存 thread ID，事件实时落盘；不等整轮结束才保存。
  控制器中断会终止自己拥有的 CLI 进程组，不影响其他会话。
- 相同会话不重复注入未变更的 Skill 原文；变更文档重新发送。
- 每次启动和 resume 都设置 `model_auto_compact_token_limit=224000`。
- 提示词通过 stdin 传递，避免系统参数长度上限。
- 研究/检查阶段有独立的可写笔记目录，目标源码仅在实现/构建/公开验证阶段可写。
- 实现/构建/公开验证允许下载依赖，Cargo 缓存在目标工作树 `.dpf-output/cargo-home`；
  不要求模型修复全局 Cargo 缓存的只读错误，也不开放冻结输入的写权限。
- 知识库 CLI 默认输出 240 字符摘要和精确定位；`show` 获取原文，`--full` 显式展开。
- `knowledge c-facts <workspace> --symbol <name>` 查询冻结的函数/类型身份、调用和布局；
  按符号限量返回，避免模型翻找完整 AST。没有匹配时不推断行为不存在。
- 同一输出错误连续重复即停止自动修正，单次最多三轮；审查/运行返工也有单次预算。

该阈值采用 Codex 的原生自动压缩配置；不是累计 API token 用量上限。
参考：[官方配置说明](https://developers.openai.com/codex/config-reference/)。

## API 与运行

执行器直接继承当前 `$CODEX_HOME/config.toml`（未设置时为 `~/.codex/config.toml`）
及其 provider/env_key/auth 配置，不在仓库中复制密钥或硬编码旧中转。
更换用户配置会改变会话身份，避免把旧 provider 的会话误用于新 provider。
`--backend sdk` 为兼容入口，现通过相同的 CLI 传输，具有相同恢复语义。

```sh
.venv/bin/python -m driver_port_factory.cli port run ../e2e-ne2000-agent-01 \
  --source-platform linux --target-platform asterinas --driver-name ne2k-pci \
  --skill-root ../C-kernel-to-Rust-upstream/skill \
  --backend exec --model gpt-5.6-sol --analyzer /usr/bin/clang-18
```

恢复运行时显式 `--skill-root` 对本次模型任务生效，历史输入记录保持原样。
不要把旧 `.codex-relay-runtime` 的配置当成当前用户配置。

## 验证边界

环境恢复优先验证最小目标启动与可用测试通道，之后复用脚本和产物。设备模型实验
仍可作为独立证据，但不能冒充目标启动成功。运行脚本等待可观察就绪或执行自动
来宾测试入口，保留整体超时；不依赖固定 sleep，也不把命令回显当作执行结果。
阶段继续作为可恢复证据检查点，不把它们扩张成新的角色或额外审查。

用户明确授权时，可用 `python -m driver_port_factory.diagnostic <workspace>` 加
`--review <REWORK报告> --skill-root <路径> --model <模型> --allow-unreviewed-diagnostic`
尝试审查未通过候选的后半程。先停止正常控制器，避免同一工作树/会话并发写入。
该入口只读正式 ledger，复用工作者上下文，将失败审查、提示词、事件与回复另存
`.dpf/diagnostic-runs/`；状态始终含 `acceptance: NOT_PASSED`。诊断不能修改驱动、
补写正式 PASS 或替代正式验收，适用于探索打包/公开 QEMU 的阻碍；不包含盲测。

`tests/test_workflow_alignment.py` 验证会话恢复、独立审查返工、自动压缩参数、
超长提示词、重复错误停止和过期产物拒绝。其源/目标仓库与模拟器是测试夹具，
通过这些测试不表示真实驱动已经在 QEMU 中验证。

真实模型/API、真实驱动和 QEMU 实跑的状态应以工作区 ledger、CAS 和运行日志为准。
旧测试中引用已删除 JSON response/CLI 接口的用例仍需迁移，不能据局部测试声称全套通过。
