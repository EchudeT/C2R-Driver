# 借鉴 v2：局部适配、简短交接和按需上下文

## 依据：pvpanic 实验 03

本轮基于 `pvpanic-behavior-sol-medium-20261003-03` 的冻结调用记录。
第一次驱动实现调用耗时 1,023.659 秒，费用估算 $3.7419672；累计输入 4,570,384 token，
其中缓存输入 4,151,808，非缓存输入 418,576，输出 20,347。
这是一次模型任务内部多次推理的累计用量，不是单次上下文窗口大小；费用是本地公开费率估算。

该回合有 55 条完成的 shell 命令、6 次 MCP 工具调用。多次返回超过一万字符的原文：
整篇 Skill workflow/translation、PCI 实现、源码搜索、控制器接口搜索和运行日志。
随后实际运行出现零地址 BAR 被目标 PCI 框架拒绝，模型请求 `target_platform_study` 返修。
旧 `retry_from` 把研究及其全部后继标记为待重做：交接、契约、实现、制品、公开验证。
代码没有丢失，但实现上下文与进度跨阶段周转。这是实际浪费，不能归因于小驱动天然复杂。
这些事实不等于每次读取都无用，也不证明新增机制已有美元降本效果。

## 从 v2 借鉴的内容

参考 `driver-port-lab/docs/architecture.zh-CN.md`：
每轮一个有意义功能，框架适配/查证/局部检查属于当前功能；持续同一会话；
简短完成状态交给控制器；完整验收仍由冻结依据与实际检查决定。
本次不复制 v2 状态机，不删除 v1 的来源、RAG、环境证据、冻结义务或最终验证。

### 1. 改变责任归属，而不是只告诉模型“少返工”

仅在 developer-evidence + unified implementation + behavior scheduling 下，
当当前实现行为尚未完成，提交 `rework target_platform_study` 会被控制器转为局部继续：

- 将原始问题报告冻结到 CAS，事件记录问题、当前行为、提交 job 和实际修复输入身份；
- 当前行为维持未完成，其他有效完成项保留，源码检查点保留；
- 原实现会话继续，先核对实际环境/固件路线，再按需查定义和实施最小框架适配；
- 不调用研究 worker，不对研究、契约和其他后继阶段执行 `retry_from`；
- 最新问题引用进入工作包，完整历史留在账本；原研究结论是历史设计依据，不能伪装成修正后保证。

这条路线不能修改冻结合同/测试标准、环境路线、仓库版本。真正需要修订这些输入仍走原显式
前置修复或 blocker；盲评、旧非统一模式、未选功能、最终制品/验收流程不适用这个转换。
若修正影响其他行为的实现前提，工作者须更新计划约束/依赖，既有调度器核对受影响进度。
最终报告必须说明修正后的前提与证据，最终验收仍绑定当前源码/制品/测试。

控制器不会自动判断一份自然语言修正是否语义充分，也不会把保留的历史分析 PASS 当成
新实现的正确性证明。判断局部影响仍有模型责任；外部质量评估与真实测试不可省略。

### 2. 局部闭环有界、可恢复

同一行为及实际实现/执行输入未变时，允许两次局部研究返修交回，第三次阻塞当前实现，
保留现场。仅改报告措辞不能清空计数。源码/必要执行输入有变化时可继续正常工作。
账本记录与进度消费之间崩溃后，重开复用原 job，不重复记录问题、不多发一个模型调用。
仍保留 64 次行为交回的总保险；它不是正常成本目标，也不限制一个模型回合内部的工具次数。

### 3. 不让模型为每轮进度写报告

新增 `driver_checks.progress(status="done"|"continue", note=可选短说明)`。
控制器绑定当前 job 和行为，生成交接文件与现有提交收据；模型不写路径、哈希或重复合规表。
调用成功后结束回合。done 最多完成当前项，continue 保持当前项；都不产生阶段 PASS。
重复提交会拒绝，不覆盖先前收据。旧 CLI 操作协议继续可用。

完整交付仍提交当前报告，保留目标合规自检、具体平台变更依据及实际验收记录；
进度短说明不能替代最终报告或运行证据。

### 4. 工作包与接口直接服务当前功能

- 精简 `delivery-task.md`：当前行为、源义务/目标前提、局部适配、按需读取、最小相关检查、交回。
- 计划建立/当前行为期间使用 `behavior-execution.md`；全部行为交回后恢复完整 `execution.md`。
  新说明进入政策摘要，变化不能继承旧验证政策。
- 详细 Skill 仍按需引用；不要求整篇重读，不要求重新调查全部目标平台。
- 平台工作包直接提供 run-case 的字段、动作、限制和可解析示例，减少为理解接口搜索控制器源码。
  示例仅检查 shell ready，不是通用设备验收；QMP 命令成功不能冒充返回值断言成功。

这不是任意截掉错误日志：原始日志与原文保留，返回路径，模型按具体问题读取。
没有新增 reviewer、每功能验收模型或知识库检索必选项。

## 验证与限制

`tests/test_local_adaptation.py` 使用合成驱动和模拟模型，经过真实提交工具、控制器、
CAS、账本、重开验证和最终采集入口；不是实际 pvpanic 翻译结果。覆盖：

- 已完成行为保留、修正留在原会话、冻结合同不变、不触发级联重置；
- 仅说明变化的重复局部请求停止，崩溃后重开不重复消费；
- 简短交接不能重复提交、不能跨过当前行为或冒充最终交付；
- 合同修订、非调度模式和盲评不能被本地化规则吸收；
- 实现工作包与最终交付工作包分别使用相应检查规则。

测试记录见 `docs/audits/local-adaptation-2026-10-03/`。
不热更新实验 03；新实验依据用户后续重启授权，使用独立冻结版本。
后续应在相同模型/版本/知识库条件下比较总费用、时间、失败重试、读取量和最终实际质量；
不能把提示词长度降低直接当成总成本降幅，更不能保证消除复杂平台适配的必要开销。

## $10 实验费用目标与停止规则

新启动参数 `--max-model-cost-usd 10` 将金额记入控制器事件账本，续跑不传参数也继续生效。
每次模型调用前检查累计记录费用，包含失败和返修；达到金额或任何历史调用费用未知时，
不再启动模型。该停止属于控制器预算边界，不会被路由为付费模型“修复预算错误”。
既有未配置预算的任务不受影响；不同金额不能静默覆盖已保存配置。

这是按调用边界执行的估算预算，不是供应商硬账单上限。一个已启动调用可能到结束才
报告用量，也可能一次跨过剩余额度；中断记录不完整时如实保留 unknown。
实验 03 已按用户指令停止，停止时已知费用约 $10.99，另有中断调用费用未知。
实验 04 使用新的冻结控制器和干净会话、同一模型及知识库种子，并配置该预算。
新一轮能否在 $10 内成功完成仍须实际验证，不能用预算阻断冒充低成本成功。
