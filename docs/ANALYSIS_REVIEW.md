# 分析审查

开发流程第 12 步产出分析、契约和测试计划后，第 13 步 `analysis_review` 由独立审查 AI
合并核对目标研究及分析材料。只有明确 PASS 才进入第 14 步实现；第 17 步最终功能审查
复用同一审查会话。工作者与审查者保持两个会话，不增加第三个角色。

新节点属于 evidence_and_design，允许按当前实际依赖回退目标研究、契约或证据。
审查发现多处问题时，完成整个指定范围的检查后一次返回所有问题，选择最早受影响的允许前置阶段；
完整报告随修复传递，后续阶段处理其中相关问题。复审保留已关闭结论，仅检查修改及影响范围。
真正的外部阻塞使用 BLOCKED。缺少尚未开始的实现或运行结果不是分析缺陷。

审查只写自己的报告目录，不改代码或工作者材料。`review.md` 引用 Skill 的证据域、证据记录、
源语义/覆盖、目标 API 与调用点、目标修改必要性、测试分类与断言来源要求。
核心通过结论同样需附具体位置；问题意见同时标明报告问题行和原代码依据行、版本、
最小片段、具体原因、影响与修复验证方法。按契约 ID 复用引用，无需复制整份代码或增加报告数据库。
程序保存结论与输入、审查规则摘要；输入或规则变化使旧结论不能自动复用。

## 审查者主动调用的定位工具

工具命令通过 `instructions.tool_runtime.evidence_locator` 提供，冻结仓库的绝对路径和
完整 commit 在 `reference_material.workspace_paths.frozen_baselines` 中。

```sh
python -m driver_port_factory.review_evidence \
  --repository /path/to/frozen/source --revision FULL_COMMIT \
  --path drivers/net/ethernet/8390/lib8390.c --start 121 --end 150
```

也可用 `--symbol 'page_lock'` 替代行号范围，先取得字面文本出现的位置，再读取上下文。
符号查找返回所有匹配的数量和最多 30 个位置，不推断哪处是定义；范围最多 200 行。
可选 `--expected-sha256 HASH` 核对文件内容。工具读取指定 Git commit 的原始 blob，
不会读取同名的其他文件、跟随源码 symlink，或把工作区未提交改动误认为冻结版本。
最大文件 8 MiB；超限、缺失、越界、哈希不符及非文本内容均返回明确 JSON 状态。

返回值含版本、路径、内容哈希、总行数和编号原文。`LOCATED` 只表示定位成功，
`semantic_verdict` 始终为 `NOT_EVALUATED`。它不是报告解析器，也不是通过/否决门禁。
审查 AI 选择调用位置、解释结果，必要时扩大调查；报告行号用普通只读命令查看。
当前修改中的 Rust 实现应按实现快照读取实际文件，不能用冻结上游工具代替。

本次增加的是新工作区的 17 阶段流程。旧运行不自动升级，不重写已有报告或重启付费迁移。
