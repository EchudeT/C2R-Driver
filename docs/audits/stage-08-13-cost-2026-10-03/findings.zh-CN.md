# pvpanic 06：08 与 13 逐请求费用审计

审计对象：`experiments/pvpanic-behavior-sol-medium-20261003-06`。只读历史模型记录、
控制器记录及真实执行收据，没有重启实验、修改候选或调用付费模型。
本实验监视器的 08 是 `environment_recovery`，13 是 `driver_implementation`；
目标平台研究是 10，其 $3.773212 的调查见
[独立报告](../target-study-cost-2026-10-03/findings.zh-CN.md)。

## 计费口径

从原生 rollout 的 `token_usage_record` 逐请求核算，不重复累加 `token_count` 通知。
累计 input、cached input、output 和费用均与阶段 metrics 一致；每条 response ID 唯一。
沿用冻结实验的单价：非缓存输入/缓存输入/输出每百万 token 分别 $4/$0.4/$20。
这些数字是项目估算，**不是中转服务的实际账单**。没有服务端缓存日志，不能断言低命中
究竟来自路由、缓存保留期限或其他服务行为。

工具动作取每条 usage 前的公开工具调用，不读取或复制模型内部推理。
请求费用包括此前全部上下文和当前输出；按动作归类不意味着费用只由该动作生成的内容造成。
累计输入是重复发送的总量，不是唯一上下文长度。

## 13：钱花在哪里

### 大量模型轮询是已证实的流程开销

30 条请求仅输出 `write_stdin`，大多数设置 `yield_time_ms=1000`。
第一次运行等待初始化日志直到 120 秒超时，产生 11 条轮询请求。
即使缓存命中，反复携带约 8 万至 11 万 token 也会收费。
13 的缓存输入费用本身达到总额的 51.7%，不能把“缓存命中”当作“几乎免费”。

第 13、14 条只是等待构建结果，但因缓存仅命中 6,912/80,298 和 12,416/78,887 tokens，
分别花 $0.2978088 和 $0.2720304。第 35、36 条是链接故障调查，分别 $0.3474128、
$0.3474784。四条合计 $1.2647304，约占 30.4%；其中两条已经计入轮询费用，不能相加。

### 实现、集成与检查顺序造成额外往返

以下为完整、互不重叠的时间区间分账，区间中可能同时包含读取、输出、缓存失效及轮询，
不能将某个区间总额全部当成可节省费用：

| 请求编号 | 实际工作 | 费用 |
| --- | --- | ---: |
| 1–8 | 规划、读取交接与 systree/PCI/组件接口 | $0.4419416 |
| 9–18 | 首次源码补丁、格式化、构建及拒收后重建、初版测例 | $0.9769656 |
| 19–30 | 首次运行与超时等待 | $0.4309160 |
| 31–48 | 排查未链接、修复、重建和首次运行通过 | $1.4504368 |
| 49–53 | 加强属性读写断言并重新运行 | $0.2363616 |
| 54–65 | 自检、缩小持锁范围、重建运行和进度交回 | $0.6187384 |

首个源码补丁请求（9）只花 $0.120328，不能把整个 $4.155 都叫“代码生成费用”。
但前面读取扩大了后续请求上下文，这个间接作用仍然存在。

真实执行共 4 次构建、4 次运行：

1. 第一次构建命令 exit=0，耗时 81.417 秒，但控制器输出
   `Source changed during build; artifact not published`。构建后的 diff 显示 Cargo.lock
   新增 `aster-pvpanic` 及依赖。这是正常依赖解析与构建输入身份检查的边界冲突；
   现有记录没有逐文件前后快照，不能将“只有锁文件变化”说成形式证明。
2. 不改驱动重新构建，耗时 8.758 秒，通过。首次运行随后耗时 120.530 秒并超时，
   guest 记录明确在等待 pvpanic 初始化日志。并非 QEMU 启动失败。
3. 排查后在 `kernel/core/src/lib.rs` 加入 `use aster_pvpanic as _;`，
   重建 60.548 秒，运行 19.498 秒通过。前后源码、构建和日志共同支持组件未实际链接的诊断。
4. 初版测例仅等待普通 `07` 文本；加强为初值检查、写入 05、拒绝 08 且保留 05，
   重新运行 27.141 秒通过。这是补上必要断言，不应将弱断言的第一次 PASS 当作完成。
5. 最后源码自检将属性读取中的格式化/复制移出自旋锁范围，重建 22.974 秒，
   运行 24.677 秒通过。该修复有具体依据，不能为了费用取消必要验证。

4 次构建累计 173.697 秒，4 次运行累计 191.846 秒；两者远小于整个行为的 952.823 秒。
剩余时间还包含模型服务、源文件检查、工具传递及其他操作，不能都归为纯模型计算。
行为交回不等于最终交付：panic_event、shutdown_event 和最终公开验收尚未完成。

## 08：等待和低缓存比日志读取更关键

该阶段继承旧会话，首请求已有 125,222 tokens。6 条轮询共 $0.7060432。
第 6 条等待请求仅输出 46 tokens，但 126,392 输入只缓存 19,200，收费 $0.437368。
第 2 条 prepare 请求为 $0.499348，缓存仅 3,840/126,828。
两条合计 $0.936716，占 44.6%，其中第 6 条与轮询分账重叠。

基线构建真实耗时 206.891 秒，启动检查 17.940 秒。构建耗时本身没有按分钟计模型费；
由模型不断发起“再等一下”会产生新的计费请求。将日志重复读取当作主要解释并不充分。
文档生成、probe 脚本及日志查看也有费用，但逐请求记录不支持把它们说成唯一或主要根因。

## 应实施的修正与可验收边界

1. **让平台长命令在受控工具内等待完成。** 当前 `driver_checks.check` 已支持脚本和已注册
   测例，但 `tool_runtime.platform_execution` 又提供直接 CLI build/run-case，实际调用走了后者。
   提供直接接入同一平台执行器的阻塞工具，统一 build/format/run-case 与环境 bootstrap 入口。
   不要求模型创建套壳脚本，不新增付费管理 agent。工具内部负责等待、超时、取消与收据；
   监视器从进程日志显示进展。保留 CLI 给人工与控制器使用。
   验收：一次长命令只有一次模型工具调用，运行中没有模型 `write_stdin` 轮询；
   失败/取消仍保存证据，所有现有来源和环境绑定继续生效。
2. **把依赖解析放到构建输入冻结之前。** 在相同容器和固定依赖策略下完成必要锁文件更新、
   记录变化，再冻结构建输入并运行构建。不能简单忽略所有 Cargo.lock 差异，不能放开源文件
   在构建中的任意变化。验收：新增本地组件不因正常锁文件生成而重复整次构建；
   非预期输入变化继续拒收，不自动重试。
3. **传递可验证的最小组件接入实例。** 具体到 Cargo/Components 注册、实际 Rust 引用和
   初始化触发位置，附适用目标版本及原始源码位置；当前行为需要新增组件时才读取。
   这比增加全平台调研更直接。知识条目必须由实际接入和运行证据支持；不能把本次缺陷故事
   自动当作跨版本通用真理。验收：案例组件真正进入镜像并被调用；不替代设备行为断言。
4. **在首次运行前准备当前行为的必要断言并做一次局部自检。** 将初值、合法写、非法写不变
   这些已冻结义务一次映射到测例，而不是先跑弱测例再补必要检查。自检留在实现会话，不新增
   reviewer 或独立阶段。之后发现真实问题仍修复并验证，不承诺一次就永不返工。
5. **保留已做的准备会话隔离，但明确作用边界。** 它针对 08/平台研究继承历史，
   13 已是新会话，解决不了它的轮询和集成返工。实现会话继续保持，不逐行为清空。

轮询的 $1.711 是观察到的请求费用，**不是已验证可节省金额**：新接口仍有启动、结果处理
和必要诊断费用，也会改变后续上下文。下一次同范围、同模型实验应分别报告调用数、
轮询调用数、失败原因、缓存/非缓存费用、完整验收结果。不能删掉 sysfs 或真实内核接入
后宣称优化成功，也不能直接用不同交付范围的 v2 数字作等价比较。

本报告只完成审计与改动规格；上述执行接口、依赖解析和集成接入改动尚未在本报告中实现，
尚无新实验费用结论。实验保持预算停止状态，未提高预算或续跑。

后续开发状态见 [平台执行交互重构](../../PLATFORM_WORKER_EXECUTION.zh-CN.md)；本报告保留原始审计口径。

## 复现

在 driver-port-factory 根目录运行（离线，无模型调用）：

```sh
.venv/bin/python docs/audits/stage-08-13-cost-2026-10-03/reproduce.py \
  ../experiments/pvpanic-behavior-sol-medium-20261003-06
```

输出 [usage.json](usage.json)，包含逐请求 token、公开工具动作、费用、轮询标记和执行收据索引。
脚本对阶段合计及 response ID 唯一性进行断言。
