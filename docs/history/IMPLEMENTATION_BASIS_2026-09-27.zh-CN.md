# 分析结论到实现的通用交接

## 问题与目标

本次 E1000 日志显示：分析原文已写明硬中断不得取得设备锁，但交付阶段没有可见的完整报告读取，旧启动摘要也没有可靠带上这条约束。重复分析并不一定意味着缺少分析，可能是有效结论没有进入当前输入。CAS 中的知识库接口文件也不等于分析报告本身。

目标是把已接受报告中的可执行结论直接提供给实现者，同时避免每轮重复整份分析。此功能面向通用驱动，不通过设备名、平台、E1000 寄存器或固定契约编号选择结论。

## 实现

- 分析节点在原报告中组织 Implementation handoff：关键约束、已证接口、未决事项、执行路径、义务与实现位置的对应关系。建议正文 6–8 千字符。没有新模型调用、报告或格式验收门禁。
- 控制器优先提取该部分原文；旧报告支持已有契约/API/未决事项章节。没有识别到有效章节时，按原文标题分段，中文标题或无标题报告也可使用，不推断各段的语义类别。
- 首次输入正文上限 12,000 字符。保留完整章节和代码块，超限部分列出标题、行号和长度；不生成半条约束或半条命令。元数据另计，不是 token 硬上限。
- 来源绑定当前已接受报告的 digest 和路径；`complete` 仅表示所选提取范围是否完整，绝不代表报告覆盖、正确性或实现完成。
- 同一会话、相同输入只完整提供一次；新会话、已识别的压缩、报告或提取策略变化后重新提供。修复轮按反馈中的字面词/编号选择完整章节，正文上限 4,000 字符，相同选择不重复注入。
- 字面匹配仅用于导航，不是根因判断。未匹配、未识别语言或超限时保留来源和位置，不宣称约束无关。目前自动修复匹配主要支持英文标识符；中文正文照常保留，但不承诺中文语义检索。
- 只有同一来源、完整原文已在启动包中出现，才删除重复的 Open decisions。外部章节或超限未决事项继续保留。
- 提示词要求在对应实现位置应用约束、区分假设和观测。既有独立复审检查实质遗漏，不把标题缺失、长度或未写编号当成缺陷。
- 上下文重置后仍读取事实交接中的未完成义务和执行状态；已内联的分析不要求再读一遍。全文始终是权威来源，必要时按行读取。

## 通用性与边界

这是确定性原文组织器，不是语义分析器。无需任何网卡专用分支。离线测试覆盖存储 DMA、USB 传输生命周期、UART、GPIO、中文报告、无标题、空交接、代码块伪标题、超长章节、未决事项去重、压缩重注入及修复去重。合成样例验证数据处理边界，不能证明这些驱动已成功迁移。

一个不规范且很长的报告可能只能提供章节位置，无法保证每个场景零额外读取。保留明确缺口比猜测语义或截掉约束更可靠。未来报告通过原分析节点的有界交接改善这一点，不追加整理模型。

## 验证与效果边界

真实 E1000 报告离线重放得到 11,255 字符的原文包，带上 C1–C8、目标 API 证据及实施顺序；包含 C6 禁止硬中断取得设备锁的原句。模拟修复反馈可定位相关原文。此结果证明输入覆盖改善，不证明模型必然遵守、功能成功或费用下降。

本次改动位于隔离分支 `fix/delivery-workflow-audit-20260927`。活动实验仍使用原工作树，没有热更新、重启或追加付费 A/B。后续应在相同输入 checkpoint 上比较首次交付遗漏、语义返工轮次、总费用及真实功能证据。

最终验证：本功能 13 项测试与分析交付、复审、决策交接、交付策略、上下文聚焦、压缩刷新、提示词及端到端交付回归，共 78 项通过。全 src/tests 的 Ruff F 检查与 git diff --check 通过。
