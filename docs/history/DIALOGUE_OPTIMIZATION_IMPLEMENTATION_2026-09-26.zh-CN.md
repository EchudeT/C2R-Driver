## 采集器的实测及证据边界

先复现旧缺陷：独立临时目录下五次无 sleep 的 QMP 查询设备并退出，旧采集器捕获
1/5。仅加入事件发现仍捕获 0/5：事件到达后启动 docker inspect/top CLI，进程可能
已经退出。加入同一 Docker endpoint 的本地只读 API 后捕获 5/5。

随后使用同一个可复用探针、同一个已存在镜像，分别测试主分支旧采集器和新实现，
包含真实 strace 宿主 docker run 绑定：

- 旧实现：10/10 QMP 设备查询成功，0/10 获得绑定的进程观测。
- 新实现：10/10 QMP 设备查询成功，10/10 获得绑定的进程观测；单次命令约 214–215 ms。

结果：[旧实现](../audits/short-container-baseline-2026-09-26.json)、
[新实现](../audits/short-container-probe-2026-09-26.json)。不同时间顺序的小样本只说明
这个已复现案例得到改善，不建立普遍漏检概率或绝对可靠性。

```sh
PYTHONPATH=src .venv/bin/python scripts/short-container-probe.py \
  --image asterinas/dev:0.18.1-20260805 --repeats 10
```

这是针对本次失败场景的 E1000 模型回归探针，不是通用流程要求，也不证明 Rust
驱动功能。通用采集器不含设备 ID 条件，不修改 harness，不注入等待或执行标记。
仍要求：本次新容器、当前工作区 bind mount、实际 top 中 QEMU 进程、镜像信息和
宿主 trace 的 docker run 关联。版本/help 仍由原规则排除。不同 PID 的同 argv
进程分别保留，同一 PID 重复采样去重。

直接 API 使用 Docker 当前 endpoint（尊重 DOCKER_HOST/DOCKER_CONTEXT）。非本地
Unix endpoint 保留 CLI 路线；事件监听启动失败或退出保留周期采样。结束时关闭事件
进程及线程。API 只发 GET，事件是触发器，不能单独进入 accepted executions。
极短进程仍可能在 inspect/top 前退出；此时记录未知/错误，不能伪造观测或自动 PASS。

## 可控读取和证据复用

```sh
PYTHONPATH=src .venv/bin/python -m driver_port_factory.read_evidence \
  --path REPORT --headings
PYTHONPATH=src .venv/bin/python -m driver_port_factory.read_evidence \
  --path REPORT --contains 'C-RESET' --budget 6000
```

工具输出精确文本片段、物理行号/列偏移、SHA256 和 next。续读使用 next 中的
`--start --column --expected-sha256`；长行不丢失，内容变化返回 CONTENT_CHANGED，
让调用者重新定位。预算约束片段输出，元信息另占少量字符。单次只读不超过 8 MiB
的普通 UTF-8 文件；更大日志使用已有定向日志工具。未匹配不等于不存在某 API，
输出不作语义 verdict；冻结 Git 内容仍用原 evidence_locator。

执行配方仍记录在当前任务的报告，不建立无版本约束的全局“成功命令缓存”。平台
版本、配置、产物、cwd 或环境变化时需重新验证。控制器只提供可靠材料引用，不从
自然语言提取命令自动执行。这能减少历史依赖，又不把旧正确结论当作永久真理。

## 检验原则与剩余验证

没有添加“看到截断就重试”“收到 collector warning 就失败”“未按模板写报告就
退回”的规则。原有已通过且输入未变化的执行回执继续复用；独立审查保留其发现
语义缺陷的职责。所有新增导航是建议，读取工具是可选能力。

已执行真实 Docker/QEMU 小探针与自动化回归，未再次运行整个翻译工程。
验证记录：全量 127 项测试通过；随后新增框架报告传递回归的 8 项定向测试通过，
当前共 128 项。新增代码基础静态检查和 diff 空白检查通过。
提示采纳、新 handoff 的端到端成本/质量影响、报告压缩后的可用性仍应在下一次固定版本完整
迁移中量化。不能把此处的 10/10 采集结果或字符预算转成未经实测的美元节省比例。

## 后续边界修复

继续检查发现，有界读取器的保守转义估算会让普通长行只用到约六分之一预算。
现改为二分查找实际 JSON 序列化长度；10,001 字符的普通长行在 1,000 字符片段预算
下用 11 页完整读回。Unicode、引号、反斜杠仍按真实转义开销计算，不靠直接截断
JSON 节省输出。搜索/标题筛选条件随 next 一起保留，避免续读悄悄变成全文读取；
越界起始行明确报出范围问题，避免看起来像成功读取空文件。

Docker 直接 API 的兼容性、权限或连接失败现在会一次性切回原 CLI 路线并记录
原因；后续采样不会反复撞同一失效 API。404/409 的已删除/停止容器属于采样竞争，
不触发整条 API 降级，也不重复查询已消失进程。该行为通过故障注入回归验证；
真实短 QMP 路线再次 5/5 获得宿主绑定观测，见
[追加探针](../audits/short-container-fallback-2026-09-26.json)。真实探针验证正常路径，
不能代替单元测试中的 API 故障场景。

本次边界修复后，全量 131 项测试通过；涉及文件的基础静态检查和 diff 检查通过。

## 首次交付自动推进：减少模型交接，而不删除证据阶段

此前只有返工能使用 prepared receipt 自动推进。首次实现即使已准备好镜像和
测试脚本，仍会单独调用模型准备产物、规划公共运行。本轮将相同机制用于首次交付：

1. 实现任务内按冻结契约/测试矩阵准备完整实现、runtime-artifact、check-presence.sh、
   public-qemu.sh 以及必要的变体和辅助文件。局部不确定行为可以先测试；完整公共
   套件交由控制器执行，避免仅为提交材料重复运行。
2. 实现快照成功后，若材料齐全，记录 `run.delivery_prepared`，绑定源文件、产物、
   检查器、公共脚本及 harness 内容。材料不齐全自动走原阶段，不新增拒绝规则。
3. 控制器继续执行原产物捕获/检查和公共运行，保存正常阶段证据。省去的是两次
   准备性模型调用；运行后的模型自查与配置的独立审查继续执行。
4. 内容变化或实现/产物阶段被重试会使旧回执失效。重开项目仍能读取有效回执；
   检查器实际失败会留下持久化 findings 并进入原处理流程，不能因文件存在而 PASS。

机制不含 E1000 名称、网络设备特定条件或历史答案，适用于通用驱动工作流。
报告的自查标记不是语义验证依据；最终质量仍依赖实际执行和审查。

合成控制器对照覆盖两条路径：准备齐全时，从框架实现到最终审查这段的 worker
调用从 5 次变成 3 次，stage_work 从 4 次变成 2 次；execution_self_check 仍为
1 次，独立审查调用不变。它使用合成源和执行器，只证明编排行为，不证明真实
驱动通过，也不代表整个迁移费用下降 40%。真实模型可能在实现阶段多花时间准备
完整交付，需要下一次固定版本完整迁移核算净收益。

本轮最终验证：全量 137 项测试通过；`ruff check src tests scripts --select
E9,F63,F7,F82` 与 `git diff --check` 通过。这是基础错误检查，不表示全仓库
全部风格规则均已通过。未启动新的付费完整迁移。

## 材料选择由控制器展开

继续对比纯 Skill 链路后，将只支持 source entry 的目录展开推广到所有经权限规则
允许的仓库 facet。模型可选择窄目录，控制器按冻结 Git tree 枚举真实文件，并在
facet 内去重；不再要求模型把已有目录机械重写为长文件列表。更早的“仅提交文件”
提示已由该能力替代。保留原始选择、展开后的绑定提案及逐文件验证，未知路径仍由
原缺口机制处理。新功能不放宽来源、修订或内容校验，也没有新增模型检查节点。

真实本地 Git 回归覆盖目录/文件重叠、嵌套、同前缀相邻目录、通配符字面文件名、
未跟踪文件排除、冻结文件删除/内容变化以及不同 facet 角色保留。历史 E1000
原始提案的只读回放和 Skill/工厂同口径交互指标见
[第二轮对比](SKILL_VS_FACTORY_COST_2026-09-26.zh-CN.md)。目录比人工精选可能更大，
因此此处验证的是表示转换正确性与无需模型枚举，不是美元净节省。

第二轮验证：全量 140 项测试通过，改动 Python 文件的基础错误/名称检查
（`ruff --select E9,F`）及 `git diff --check` 通过。历史回放仅执行本地只读 Git
查询，未改写历史运行或启动新的付费模型任务。

## 检索结果按证据去重，摘要定位命中处

搜索现在先过滤/排序，再合并仅记录 ID 不同的同源同内容片段，最后应用结果上限。
所有其他元数据都参与同一性判断，其他记录 ID 放在 `also_indexed_as`；原始 chunk
与 `show` 行为不变。compact 摘要由片段开头改为命中位置附近，附带原文行号。
生成的项目知识库 Skill 接口说明已同步，明确摘要仅作导航。

新增回归覆盖去重先于 limit、原始索引不变、record_id 过滤、不同来源/修订/角色/
行号/authority 不误合并、摘要词定位及完整性失败仍传播。历史语料只读回放显示，
两条具体符号查询在不同片段数不变的情况下输出字符减少约 37%；多词查询因增加
导航信息也可能变大，不能把局部字符变化当作端到端费用收益。

第三轮验证：全量 147 项测试通过，改动 Python 文件的基础错误/名称检查
（`ruff --select E9,F`）及 `git diff --check` 通过。本轮没有付费模型调用。

## 批量知识查询

新增 `knowledge search-batch RUN --queries-file FILE`：一批问题共享一次已校验
索引快照和文档来源表，每题结果/过滤/排序/摘要/别名保留。调用间不缓存完整性
结果，修改后的材料仍会被下一次查询检测。项目知识库生成器提供命令和用法，
query contract 兼容旧四命令版本，仅将 search_batch 作为可选扩展。

回归覆盖 compact/full 批量输出无损还原单条结果、一次加载、下一次调用重新
校验、非法选项在加载前报错及新旧合同兼容。真实历史七问只读回放的格式化输出
从 53,799 降至 49,334 字符，56 条命中和排名保持一致；CLI 实际调用也已验证。
这个局部收益不能换算为完整迁移费用；详见第四轮对比及其机器记录。
