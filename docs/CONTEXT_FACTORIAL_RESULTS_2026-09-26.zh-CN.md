# 四组上下文与机制证据实验

## 授权和执行方式

用户明确表示暂时不必受之前预算顾虑限制，但应适量使用。本轮据此建立新的后继协议，允许响应缺少输出上限回显，将其作为 warning 记录；保留固定 8 次调用、每组 2 次、已有超时、实际输出超限/模型身份变化/usage 未知/调用失败时停止后续请求、不自动重试。原已阻止协议和限额探针不修改。

这不是恢复中转的输出限额功能：该中转此前确实发生过超限，客户端超时也不是服务端计费硬上限。新的策略是按用户授权执行固定规模实验并记录实际用量。默认实验策略仍要求确认上限；新策略只在显式协议 `limit_policy=observe_actual_usage` 中生效，不影响生产驱动验收。

[新协议与完整原始产物](experiments/context-factorial-authorized-2026-09-26/)保留 predecessor protocol SHA-256。模型为 gpt-5.6-sol、medium reasoning，请求 4096 输出上限、900 English words 任务说明，不开放工具。相同输入和 rubric、两个反向顺序区组，在调用前冻结。

## 比较什么

| 组 | 相同当前代码/契约/最新 receipt/旧归因 | 重复旧 receipts 与报告 | 设备机制与目标接口摘录 |
|---|---|---|---|
| compact | 有 | 无 | 无 |
| history | 有 | 有 | 无 |
| compact_mechanism | 有 | 无 | 有 |
| history_mechanism | 有 | 有 | 有 |

所有组都得到同一条历史 collector 归因，解决首轮交接组未获得旧归因却被要求纠正它的问题。历史组仍包含额外报告内容，因此不宣称所有信息完全等价。机制组额外获得约 2.9 KB 的原始源码摘录，包括 Linux shared IRQ、QEMU INTA/pci_set_irq 和目标可选 MSI-X API；这是有意操纵的知识因素，不是零成本自动生成的知识。

评分为调用前冻结的六项 rubric：纠正旧观察归因；识别假功能证据；保留真实数据路径及范围；区分设备机制与通用 API；提出有界下一步且不弱化范围；分离事实/主张/未知。人工逐条评阅，评阅者知道组别，不是独立盲测。关键单项比总分更有解释力。

## 实验结果

8 次全部完成，实际输出均未超过请求的 4096 token；8 次上限回显仍为 null，只能说明本组实际用量，没有证明服务端限额有效。合计公开费率估算 **$0.7996352**，累计已知估算 **$1.3586496**。没有后续追加采样。

| 组（各 2 次） | 输入 token | 缓存 token | 估算费用 | 时长中位数 | rubric 平均分 | 明确指出 INTA/可选 MSI-X 区别 |
|---|---:|---:|---:|---:|---:|---:|
| compact | 20,550 | 0 | $0.1507400 | 79.931s | 5.5/6 | 0/2 |
| history | 66,032 | 32,896 | $0.2273424 | 45.061s | 5.5/6 | 0/2 |
| compact_mechanism | 22,562 | 0 | $0.1900680 | 59.149s | 6/6 | 2/2 |
| history_mechanism | 68,044 | 33,792 | $0.2314848 | 47.867s | 6/6 | 2/2 |

所有回答都纠正了 collector 旧归因，识别了 marker/Loopback/伪 PASS，并保留设备功能义务。机制证据四次均带来明确的 INTA/共享中断与可选 MSI-X 区分；无机制证据的四次没有这一具体区分，其中两次仍明确表达中断模式适配未知。具体机制区分的计数是事后解释性指标，不是另一个预注册主要终点。

rubric 总分接近上限，C4 一分差异依赖人工判断“泛化的不确定”是否足够具体，不能据此宣称稳定质量差距。更有价值的观察是：不到 3 KB 的机制材料，使回答定位到此前反复遗漏的必要核实。该证据经过人工选择，不能把收益归因于完全自动工作流。

缓存使长组第二次调用更便宜：history $0.0558984、history_mechanism $0.0538968，而未命中缓存的 compact 为 $0.0687、compact_mechanism 为 $0.102964。短组也没有更低的时长中位数。因此不能把首轮“短组更快”的观察外推。

[逐调用人工评阅及原始 usage](experiments/context-factorial-authorized-2026-09-26/assessment.json)保留全部数据，不把估算当实际账单，不用诊断分数替代驱动功能测试。

## 本轮落地的通用改进

### 能力映射先检查前置条件

target study 与 framework enablement 的提示现在要求：对当前影响最大的未决能力，查所选设备真实机制、目标 API 前置条件及相近调用路径，在原报告中引用短摘录，说明最小反证检查。可选 capability API 不代表设备拥有该 capability。证据缺失不等于全平台不支持。

这是定点证据检索指导，不新增大表、模型评审或机械 gate；不要求所有驱动都检查 IRQ/DMA，也不要求设计阶段执行全部行为。实验测的是补充机制证据，尚未直接测量该提示修改能否自动检索到同样的证据。

### 重复观察后仍保留最近一次转变

上一版本只保留最近两条 observation，若 false→true 之后再次 true，两条之间没有变化，交接会丢掉重要转折。本轮保留原 recent/changes 接口，另带 last_transition：在同一修复周期、最多 32 条相关事件内，穿过相同 observation，保存最近一对有变化的来源记录。

不跨 unknown/空 observation/不一致字段集合继续追溯，不跨 stage PASS 或显式 reopen。没有变化时为 null。只额外保留一对历史记录，不复制全部日志，不自动宣布旧假设已经证伪或功能已通过。

### 修正提示与实际 preflight 的冲突

阶段目标中遗留“拒绝 uncontinued -S 和 unbound runtime”的旧说明，但实现已将表面上的暂停/变量缺失设为 advisory。现同步为：marker 仍拒绝；helper 或外部控制可能完成恢复/绑定，应以实际观察判断。避免模型因为旧提示修改本来合法的 harness；没有降低真实运行证据要求。

### 源码调查应避免新的过度归因

实验进行期间进一步检查冻结目标源码，发现 `IrqChip::map_gsi_pin_to` 已存在，委托 `ioapic.enable`，并持有映射生命周期对象。非 remapped 路径直接写 IRQ vector，所检查接口未暴露触发方式/极性参数。真正待核实的仍是 PCI pin→GSI 路由、共享/电平触发与生命周期，而不是简单宣称“目标没有 INTx”。

这些新摘录没有进入已经冻结的实验。来源哈希和片段单独保存在 [后续 IRQ 源码审计](audits/irq-routing-followup-2026-09-26.json)。没有修改目标驱动或声称验证了可运行的中断路线。

## 结论边界

本轮是单个已知失败 checkpoint 的文本诊断，未运行 guest、编译驱动、做代码修复或原生 thread resume。两个重复不足以估计稳定成功率、跨驱动泛化或统计显著性；计价是本地公开费率估算，未对账。上下文组之间的成本不能直接外推到完整迁移。

下一步应优先把短小的关键机制证据用于真实能力核实和最小可执行里程碑，而不是继续在同一个 checkpoint 无限抽样。默认生产会话继续复用，选择性重置仍 opt-in。任何正式研究需跨设备案例、固定环境/预算/共同功能 oracle，并记录证据提取和人工工作量。
