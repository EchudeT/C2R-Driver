# Skill 工作任务协议：修复与验收

日期：2026-09-20。范围：公开迁移，不含盲测。本文记录实现结果，不改写原始审查结论。

## 一致的执行协议

Skill 规定实质要求；项目的 `orchestration/protocol.py` 定义任务操作、完成出口与修复目标。
通用提示只说明权限、证据边界、持久上下文和报告提交；阶段目标说明当前工作。
运行时从真实依赖生成已存在输入和合法修复目标，从中间收据生成工具就绪状态。
操作标记的校验与执行使用同一个解析器，而非各阶段自行匹配字符串。

工作者主要交付代码、脚本和 Markdown；控制器负责编译事实、快照、哈希、收据与状态。
保留 Skill 的自检，不增加交接表格或固定的第二轮全文审查。

## 对照阶段边界审查

| 问题 | 实现 |
| --- | --- |
| B1：要求先于证据 | 合并旧13/14为一个 source_closure 任务：编译输入→SOURCE_ANALYSIS→读取事实→覆盖自检。总流程19阶段。 |
| B2：未生成被当作损坏 | 查询依据实际中间收据判断可用性；未就绪说明当前任务所需操作，已有事实可重建导航。 |
| B3：按编号全量回退 | 依赖图区分调度顺序与数据输入；只失效后代。源码补证不失效环境，目标研究以相关输入身份验证复用。 |
| B4：KB权限冲突 | 项目生成与实际只读查询权限一致的 KB Skill，修改清单/重建归控制器所有，查询自己验证输入。 |
| B5：本地依赖重复补证 | SOURCE_ANALYSIS 内发现并纳入冻结仓库的编译依赖，不额外要求证据阶段先行填表。 |
| B6：打包改动完整重做实现 | 打包导致实现快照变化时，要求受影响检查和自检，再刷新快照、重新捕获产物，不追加实现模型调用。 |
| B7：事故专用确认守卫 | 删除临时“再确认一次”提示与专属分支。 |
| B8：两套输出接口 | 删除旧目标研究 JSON 多表入口与旧源码闭包 JSON 实现；统一自然报告和 compile_commands 接口。 |
| B9：缺完整协议测试 | 验证真实编译输入→操作→查询→重开项目→复用→自检结束，以及依赖回退、目标研究复用、打包重快照与旧运行升级。 |

删除的受 Git 管理代码可从历史恢复；不保留旧执行架构。历史账本保持不可变，升级投影只识别
被退休的静态检查点，不执行旧流程。

## 验证记录

- 全量：282 passed，41 subtests passed，178.05 秒。
- 统一操作解析后的针对性复验：16 passed，18.28 秒（源码协议、公开 QEMU、控制器）。
- 实际 audit-01 一次性升级成功：旧1–12保持 PASS，源码阶段 READY；完整账本/产物完整性验证通过。
- 实际生成 KB Skill 的 quick_validate 通过；直接调用提示组合器核对源码任务和所附上游 Skill。
  CLI prompt render 要求 RUNNING，未为了预览而改变运行状态。
- 未启动付费模型，未向工作者发送私下指令，未修改工作者报告或伪造完成状态。
- 升级只保留一份 SQLite 恢复快照 `.dpf/pre-protocol-upgrade.sqlite3`。

## 尚不能由离线测试证明的事项

完整迁移和 QEMU 全程尚未在新协议下执行，不能承诺费用低于30美元或不会遇到编译问题。
目标研究复用使用保守的非源码证据身份；相关证据变化仍要求复查，不假装程序能判断语义等价。
Markdown 内容的正确性仍依赖工作者自检和真实测试，不把哈希完整性当成语义证明。
控制器仍有有限纠错/操作续接预算；超限应停止并保留证据，不自动回退无关阶段或无限付费重试。
