# 回修 Prompt 统一组织

本轮收敛 E1000 阻塞修复新增的提示内容，不启动付费运行。

## 结构

- `instructions.protocol`：通用提交/路由协议与冻结输入权威，不再重复回修状态解释。
- `instructions.delivery_repair`：仅交付修复使用的构建、包装、执行规则。原先也叫 repair_task，现与问题报告明确区分。
- `reference_material.repair_task`：当前回修唯一入口，包含触发报告 CAS 引用、有界摘录、调度状态和历史执行观察。前置完成不等于发现关闭的规则仅在此陈述。
- 不存在绑定报告的手工恢复/执行纠错仍保留原反馈，不编造问题归属。

删除 repair_scope 的重复指令；有回修报告时，把 repair_state 和 repair_focus 合入同一入口。只合并哈希或 CAS 路径完全相同的报告别名，保留不同版本和当前工作报告。阅读导航在整理之后生成，避免指向已经删除的别名。

## 内容预算与会话

报告正文预算从 10,000 降为 6,000 字符。短报告完整提供；长报告优先分配空间给明确提到当前阶段的章节，其余章节仍提供导航摘录。字符串匹配仅决定展示顺序和预算，不证明某问题与本阶段无关，更不关闭问题。未按标题组织的长文本退回有界摘录与完整原文引用。

同一会话、同一阶段、同一报告与摘录只内联一次；再次提供源引用、状态和观察。新阶段、新会话、重置、报告或摘录变化均重新内联。保留“已提供不等于已读/记住”的提示，原文始终可读。此处使用现有 session.inputs，无新增模型调用或检查门槛。

## 验证与限制

回归覆盖重复报告去重、不同证据保留、输入对象不被修改、同阶段复用、新阶段/新会话/变化重新注入，以及实际控制器回修提示与上下文策略。

实际 E1000 首次审查报告用于离线构造检查，未启动模型。片段长度减少不等于账单同比下降；缓存、工具读取及修复成功率仍需完整实验衡量。这里统一的是回修上下文，不宣称整个工作流所有提示已达到零重复。

## 原生压缩后的重新交接

已增加 `codex/compaction.py`，在每次模型调用前按线程身份读取原生 rollout 的新增完整记录，识别顶层 `compacted` 事件。事件触发当前输入去重缓存失效，使问题摘录、Delivery essentials、已接受决定和探针配方在下一次交接重新提供；不会重放整段对话或所有 Skill 正文。

扫描游标随成功交接的 session.inputs 保存；同一压缩只触发一次，新压缩再次触发。调用内发生的压缩不会被调用结束时提前确认，因此下一次调用仍能识别。失败调用不确认游标；不完整 JSONL 尾行留待下次读取。日志替换/截短会保守失效输入去重，但不伪称发生压缩。日志缺失、格式异常或身份不匹配不阻塞运行，metrics.native_compaction 记录观测结果。

目前不使用累计计费 token 或单次输入突然下降推断压缩，避免误判导致反复注入。只识别已支持的明确原生事件；未支持的日志格式仍属于不可观测。长时间 codex exec 内发生压缩，外层在下一次交接补入，调用期间仍可按 CAS 路径重读。
