# 原生会话与单节点实验的适用边界

## 结论

当前不能声称“舍弃历史比保留历史更好”。此前 factorial 实验是新 Responses 请求中的文本对照，能比较给定材料下的诊断回答，不能估计完整迁移中重置会话的净收益。长上下文组也不是原生跨阶段会话。该限制适用于通用驱动翻译，不能因为 e1000 的个例改变默认策略。

用户指出的差异成立：全程运行的原生会话可能携带工具结果、先前决定、失败尝试及压缩摘要。压缩后当前输入未必包含所有历史原文；累计 input_tokens 又包含多次请求的重复输入，不能当作当前上下文长度。设置 auto_compact_token_limit 也不证明实际发生过压缩。

## 已落地的观测改进

`codex context-report` 增加 `session_lineage`，从已有本地 sidecar 显示每个调用是否记录为新建或续接，以及同线程此前调用数和阶段。即使指定 `--stage driver_implementation`，仍从完整运行记录计算此前阶段，避免过滤后误以为节点没有历史。

未知的续接状态保持 unknown；缺少早期记录的续接标为 resume_without_prior_record。实际有效上下文和压缩次数保持未知，不从阈值、缓存率或阶段 PASS 推断。不同线程可能属于独立 reviewer，报告不把线程变化一律解释为重置。

这是只读观测，不增加验收门槛、重试或模型调用。现有 persistent 默认策略保持不变。

## 下一轮有效实验的设计

1. 从可保留原生会话的运行中，在预先指定的阶段边界同时冻结工程状态、契约、最新回执、工具和模型配置，保存会话 ID 与 rollout 摘要哈希。不要从已经失败的结果反选有利节点。
2. A 组 fork 同一原生会话；B 组新建会话，只接收事实交接。两组从同一工程快照的独立工作区开始，得到相同任务和证据访问权限。若比较完整的重置策略，交接摘要生成成本也计入 B 组。
3. 先做少量诊断可行性试验，再执行有界的修复/实现窗口。诊断试验只判断信息保存，不能替代可执行驱动验证。缺失长会话时不能用拼接文本冒充原生 fork。
4. 交替调用顺序，记录实际缓存、端到端时间、工具重读量、完整费用和未完成调用。fork 可能携带累计计数，必须确认计费增量基线，不能把整个父会话的消耗归入实验。
5. 质量评价关注设备义务、构建、可执行设备行为和失败恢复。要提出通用驱动结论，需要扩展到其他驱动类型与多个独立运行。保留每组失败和不确定结果，不因缺一句术语就拦截继续工作。

暂不为缺失历史的所谓“全程对照”付费。本次没有新增付费调用。更有依据的候选策略仍是：在契约冻结等边界尝试事实交接；保留约束、证据、当前代码状态和已证伪方案，减少过时诊断和重复日志。它是待验证假设，而非已证明优于持续会话的结论。
