# 阅读导航、变化驱动修复与按需探针

本轮沿用分析到执行的一次性交接，优化进入新会话后如何查找材料，以及连续修复时如何关注新增证据。没有增加固定节点、审查调用或验收条件，也没有降低驱动功能义务。

## 已实现的行为

### 按阶段阅读导航

控制器对本次实际提供的产物引用生成 `reading_plan`，最多列出 8 个优先位置，重复的 kind/digest 合并。其余引用仍完整保留，不根据排名删除证据。

- 框架使能：契约、目标研究、测试矩阵、已有分析审查。
- 驱动实现：契约、测试矩阵、框架报告、目标研究。
- 制品准备：合规报告、目标变更清单、契约。
- 公共验证：测试矩阵、制品身份、合规报告。
- 有变化的证据优先；没有匹配内容时不生成空导航。

位置指向原上下文，交接文件中的位置则指向该交接文件。提示明确：未变化只说明此前提供过，不证明模型读过，也不证明结论正确。二进制包不应按文本打开。导航是建议顺序，不能用来判定材料缺失或接受结果。

### 变化驱动的修复输入

在继续执行、修复和检查器反馈调用中，`repair_focus` 提供本修复片段的最新观测、最近差异、重复观测之前的最后一次变化及回执位置，同时列出变化的输入引用。跨已完成或显式重开的阶段不沿用旧修复片段。

历史观测不替代当前代码检查，引用摘要变化不等于完整代码 diff，也不证明因果关系。当前控制器反馈优先；已解决的前置修复不重新解释为待修缺陷。错误文本重复本身不作为新阻断条件。既有执行复用仍由输入绑定的回执决定；本模块不另行授权跳过检查。

没有历史观测或变化引用时不生成空摘要，不为获取摘要调用模型。

### 长反馈按需读取

超过 6,000 字符的文本型 controller_execution、controller_feedback 或 checker_findings 写入不可变 CAS，提示保留开头 1,500 字符、末尾 1,000 字符及完整记录引用。原文完整保存，包含 Unicode 和换行；重复文本复用同一对象。

摘录不是完整错误清单。模型需要在修复或接受结果前检索完整记录的相关内容，被省略的发现仍然有效。短反馈、结构化反馈及其他字段保持原样。这是传输与读取策略，不是语义摘要或错误过滤器。

### 按不确定性选择小探针

在已有框架使能节点中，优先用能区分竞争解释的最小检查验证关键未知前提，例如接口能否调用、DMA 所有权或中断路由。已有证据能够回答时直接复用，不要求所有驱动跑 DMA/中断清单。探针遵守该节点可修改路径，不把驱动集成偷偷移到框架节点。

在实现节点中，优先完成真实目标插入、初始化和首个适用设备操作，再扩展其余义务。编译通过只证明对应编译性质，不等于设备运行正确。命令、输入、观测和剩余未知写入已有报告，不新增报告格式、自动探针调度器或模型回合。此部分是执行策略指引，尚不是已经在真实驱动上验证的收益。

## 离线证据与成本边界

对 `/tmp/e2e-e1000-local-baseline-02` 的 28 份历史提示进行了只读离线回放，完整摘要见 [审计记录](audits/context-focus-offline-2026-09-26.json)。原运行没有改动，临时 CAS 独立存放并在结束后清理，没有付费模型调用。

可复现命令：

```
PYTHONPATH=src .venv/bin/python scripts/context-focus-audit.py /tmp/e2e-e1000-local-baseline-02
```

- 19 份提示生成了阅读导航，单份导航最多 891 字符。
- 没有反馈超过归档阈值，因此这一样本的长反馈压缩没有节省输入字符。
- 这些是字符统计，不是 token 或费用统计；没有模拟后续模型选择，也没有证明端到端节省。

导航和观测摘要本身增加少量输入，目标是减少后续无效检索与重复修复。是否值得，应在后续原生会话实验中一起统计工具重读、失败迭代、实际缓存费用、首个设备操作和最终义务完成情况，不能仅比较单次提示长度。

本轮没有扩展跨运行知识库，也没有建立跨驱动验证缓存。两者需要可靠的版本、环境及语义适用范围，直接复用旧结论可能比重查更昂贵；先用本轮机制收集真实重复工作，再决定哪些机制知识值得固化。

验证：全量 114 项测试通过；随后补充的提示组装集成测试包含在 5 项定向测试中，均通过。覆盖导航不丢失引用、长反馈原文完整保存、重复观测下保留变化、修复片段隔离及实际 worker 提示组装。没有运行新的真实驱动迁移。
