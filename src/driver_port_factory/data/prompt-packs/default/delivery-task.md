# One complete delivery task

Deliver the driver, necessary framework/integration changes, runnable artifact and required public
harness together. The controller has separate evidence checkpoints, not separate owners for shared
source files. Read Delivery essentials if supplied, then relevant authoritative contract/test details.
A short excerpt is not a substitute for all required obligations.

Before broad coding, identify driver-owned stimuli and observations required by the final matrix:
which existing interface exercises them, which small hook is genuinely needed, and how the current
build route inserts the driver. Do this in the existing working plan/report, not a new planning turn.
Do not freeze a smoke-only implementation and defer known source-dependent test entrypoints to a
later packaging task. Reuse production interfaces where possible; do not build a generic test framework.

Use accepted_decisions and applicable recent probe recipes first. Prioritize the one or two unresolved
questions most likely to change the implementation route; resolve them with existing evidence or the
smallest relevant check, without a new planning turn. If no such uncertainty remains, start coding.
An old COMMAND_OK/MATCH is a historical observation, not current validation. Then establish
a real end-to-end operation, and complete the required behavior and its observation together. Change
framework code only when the actual selected device mechanism cannot use an existing target interface.
Check the definition and a real call site before declaring a gap. Reuse the successful command, cwd,
features and container route; do not rediscover them from generic workspace commands after compaction.

Order implementation around costly rework: wire the required production/test entrypoint into the
actual artifact first, then establish one observable end-to-end operation before expanding behavior.
Implement each mechanism's applicable failure/recovery path alongside its successful path, while
ownership and state transitions are still local. For length-sensitive operations distinguish valid
data from allocated capacity; for publication establish readiness first; for temporary diagnostics
restore state on every relevant exit. Apply these only where source obligations require them.
Check a negative control's stimulus before trusting its result. Do not postpone these decisions to
packaging or final review, and do not turn this order into a mandatory extra test suite or report.
Batch independent source/API/test lookups; serialize edits and probes sharing a worktree or artifact.

Do not add irrelevant DMA/IRQ/network checks to a driver that does not use them.
Compile locally as needed, but run each unchanged passing full
public suite once through managed execution and consume its receipt. Review observations in this same
task when available and explicitly acknowledge the final report; independent final review stays separate.

Deliver runtime-artifact, check-presence.sh, implementation-smoke.sh, public-qemu.sh and required
helpers under .dpf-output/. Preserve exact input/output identities. A complete prepared delivery can
cross later bookkeeping stages without another worker call; incomplete preparation gets an ordinary
continuation, not a formatting rejection. Update the current report instead of appending contradictory
historical verdicts; old immutable evidence remains available.

During repair, start from the actual finding, current source and affected oracle. Preserve unrelated
passing work. A public harness/oracle error with unchanged driver behavior does not require rewriting
the driver; a source fix does require rebuilding and testing the affected artifact. Expand testing only
when the changed mechanism can affect additional required behavior. Stop after the causal defect and
its relevant regressions are resolved; defer optional cleanup and speculative improvements.

Detailed Skill guidance is available by reference for concrete questions. This task and the frozen
scope control work scheduling; reading a reference does not add another phase, report or model review.
